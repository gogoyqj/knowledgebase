NestJS 整体架构

NestJS 采用分层架构，将应用分为 Controller → Service → Repository 三层，每层职责清晰，便于测试和维护。

🌐 HTTP 请求
↓
🛡️ 中间件 (Middleware)
↓
🔒 管道 (Pipe) · 守卫 (Guard) · 拦截器 (Interceptor)
↓
🎮 控制器 (Controller)
↓
⚙️ 服务 (Service / Provider)
↓
💾 数据访问层 (Repository / Prisma / TypeORM)
hub

请求生命周期

每个请求经过以下阶段：

  1. 中间件 (Middleware) — 最先执行，可访问 req/res 对象
  2. 守卫 (Guard) — 认证/授权逻辑，决定请求是否可继续
  3. 拦截器 (Interceptor) — 请求前后处理，可转换响应/异常
  4. 管道 (Pipe) — 参数验证与转换
  5. 控制器 (Controller) — 处理请求，调用服务
  6. 服务 (Service) — 业务逻辑
  7. 异常过滤器 (Exception Filter) — 统一异常处理
info
拦截器的 before 部分在管道之前执行，after 部分在管道之后执行。

// main.ts
import { NestFactory } from '@nestjs/core';
import { ValidationPipe } from '@nestjs/common';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  // 全局管道 - 自动验证 DTO
  app.useGlobalPipes(new ValidationPipe({
    whitelist: true,        // 自动剥离未定义属性
    forbidNonWhitelisted: true, // 未知属性抛异常
    transform: true,       // 自动转换类型
  }));

  await app.listen(3000);
}

装饰器模式

NestJS 大量使用 TypeScript 装饰器，将元数据附加到类和方法上：

// 类装饰器
@Controller('users')
@ApiTags('Users')
export class UserController {

  // 方法装饰器
  @Post()
  @HttpCode(201)
  @UseGuards(AuthGuard)
  @ApiOperation({ summary: '创建用户' })
  create(@Body() dto: CreateUserDto) { // 参数装饰器
    return this.service.create(dto);
  }

  @Get(':id')
  findOne(@Param('id', ParseUUIDPipe) id: string) {
    return this.service.findOne(id);
  }
}

// 自定义装饰器
export const CurrentUser = createParamDecorator(
  (data: string, ctx: ExecutionContext) => {
    const request = ctx.switchToHttp().getRequest();
    const user = request.user;
    return data ? user?.[data] : user;
  },
);

策略模式 (Strategy Pattern)

Passport 集成是策略模式的典型应用，不同认证方式封装为独立策略：

// JWT 策略
@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy) {
  constructor(private config: ConfigService) {
    super({
      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
      secretOrKey: config.get('JWT_SECRET'),
    });
  }

  async validate(payload: JwtPayload): Promise<User> {
    return { id: payload.sub, email: payload.email };
  }
}

// Local 策略（用户名密码）
@Injectable()
export class LocalStrategy extends PassportStrategy(LocalStrategy) {
  async validate(username: string, password: string): Promise<User> {
    return this.authService.validateUser(username, password);
  }
}

代理模式 (Proxy Pattern)

拦截器 (Interceptor) 本质是代理模式，在方法执行前后插入逻辑：

// 缓存拦截器 - 代理原始方法
@Injectable()
export class CacheInterceptor implements NestInterceptor {
  constructor(private cacheManager: Cache) {}

  async intercept(
    context: ExecutionContext,
    next: CallHandler,
  ): Observable<any> {
    const key = this.trackBy(context);
    const cached = await this.cacheManager.get(key);

    if (cached) {
      return of(cached); // 返回缓存
    }

    return next.handle().pipe(
      tap(response =>
        this.cacheManager.set(key, response, 60)
      ),
    );
  }
}

动态模块 (Dynamic Module)

动态模块允许在导入时传入配置，运行时动态生成模块：

@Module({})
export class DatabaseModule {
  static forRoot(options: DbOptions): DynamicModule {
    return {
      module: DatabaseModule,
      global: options.isGlobal,
      providers: [
        {
          provide: 'DB_OPTIONS',
          useValue: options,
        },
        DatabaseService,
      ],
      exports: [DatabaseService],
    };
  }
}

// 使用
@Module({
  imports: [
    DatabaseModule.forRoot({
      host: 'localhost',
      port: 5432,
      isGlobal: true,
    }),
  ],
})
export class AppModule {}

scope

Provider 生命周期 (Scope)

DEFAULT 单例

整个应用共享一个实例，性能最优。默认行为。

REQUEST 请求级

每个请求创建新实例，请求结束销毁。可注入 Request 对象。

TRANSIENT 瞬态

每次注入创建新实例。适合有状态的 Provider。

// 作用域级别性能对比
@Injectable({ scope: Scope.DEFAULT })   // ⚡ 最快 - 全局单例
@Injectable({ scope: Scope.REQUEST })   // 🐢 每请求新实例
@Injectable({ scope: Scope.TRANSIENT }) // 🐢 每注入新实例
warning
REQUEST scope 会破坏单例优势，在微服务/高并发场景慎用。用 CLS_MODULE_OPTIONS 替代。

守卫 (Guard)

守卫负责认证和授权，返回 true/false 决定请求是否继续：

// 角色守卫
@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const roles = this.reflector.getAllAndOverride<string[]>(
      ROLES_KEY,
      [context.getHandler(), context.getClass()],
    );
    if (!roles) return true;

    const { user } = context.switchToHttp().getRequest();
    return roles.includes(user.role);
  }
}

// 自定义角色装饰器
export const Roles = (...roles: string[]) =>
  SetMetadata(ROLES_KEY, roles);

// 使用
@Roles('admin')
@UseGuards(RolesGuard)
@Delete(':id')
delete(@Param('id') id: string) {}

管道 (Pipe)

管道用于参数验证和转换，是数据清洗的第一道防线：

// 使用 class-validator 验证 DTO
import { IsString, IsEmail, MinLength, IsOptional } from 'class-validator';

export class CreateUserDto {
  @IsString()
  @MinLength(2)
  name: string;

  @IsEmail()
  email: string;

  @IsString()
  @MinLength(8)
  password: string;

  @IsOptional()
  @IsString()
  avatar?: string;
}

// 自定义管道
@Injectable()
export class ParseObjectIdPipe implements PipeTransform {
  transform(value: string) {
    if (!Types.ObjectId.isValid(value)) {
      throw new BadRequestException('无效的 ID 格式');
    }
    return value;
  }
}

拦截器 (Interceptor)

// 响应转换拦截器
@Injectable()
export class TransformInterceptor<T>
  implements NestInterceptor<T, Response<T>> {

  intercept(
    context: ExecutionContext,
    next: CallHandler,
  ): Observable<Response<T>> {
    return next.handle().pipe(
      map(data => ({
        code: 200,
        message: 'success',
        data,
        timestamp: new Date().toISOString(),
      })),
    );
  }
}

// 日志拦截器
@Injectable()
export class LoggingInterceptor implements NestInterceptor {
  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const now = Date.now();
    return next.handle().pipe(
      tap(() => console.log(`耗时: ${Date.now() - now}ms`)),
    );
  }
}

异常过滤器 (Exception Filter)

// 统一异常过滤器
@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();
    const request = ctx.getRequest<Request>();

    const status = exception instanceof HttpException
      ? exception.getStatus()
      : 500;

    const message = exception instanceof HttpException
      ? exception.getResponse()
      : 'Internal server error';

    response.status(status).json({
      code: status,
      message: typeof message === 'string'
        ? message
        : (message as any).message,
      path: request.url,
      timestamp: new Date().toISOString(),
    });
  }
}

// 注册为全局过滤器
app.useGlobalFilters(new AllExceptionsFilter());

四者核心差异

Guard、Interceptor、Pipe、Filter 各司其职，互补而非替代：

🛡️ Guard — 放行/拒绝

  • 职责：认证/授权，决定请求是否放行
  • 返回：boolean — true 放行，false 抛 403
  • 时机：在 Interceptor 和 Pipe 之前
  • 能否访问响应：❌ 只看请求
  • 典型：角色检查、JWT 验证、IP 白名单

🔄 Interceptor — 增强处理

  • 职责：请求/响应的增强与转换
  • 返回：Observable — 可转换/缓存响应
  • 时机：包裹控制器，before 在 Pipe 前，after 在后
  • 能否访问响应：✅ 可处理响应（tap/map）
  • 典型：响应格式化、缓存、日志、超时

🔧 Pipe — 验证/转换

  • 职责：参数验证与类型转换
  • 返回：转换后的值，或抛 BadRequestException
  • 时机：在 Interceptor(before) 之后、Controller 之前
  • 能否访问响应：❌ 只处理入参
  • 典型：DTO 验证、ParseIntPipe、自定义校验

🧯 Filter — 异常处理

  • 职责：捕获异常，统一错误响应
  • 返回：格式化的错误 JSON
  • 时机：最后防线，Controller/Pipe/Guard 抛的异常
  • 能否访问响应：✅ 格式化错误响应
  • 典型：统一错误格式、异常日志、404/500 页面
tips_and_updates
简单判断：问"能不能访问？"→ Guard ｜ 问"怎么处理？"→ Interceptor ｜ 问"参数对不对？"→ Pipe ｜ 问"出错了怎么办？"→ Filter

代码组织最佳实践

1. DTO 模式 (Data Transfer Object)

入参和出参分离，使用 class-validator 验证
// 请求 DTO - 验证入参
export class CreateUserDto {
  @IsString() @MinLength(2) name: string;
  @IsEmail() email: string;
}

// 响应 DTO - 控制出参
export class UserResponseDto {
  @Expose() id: string;
  @Expose() name: string;
  @Expose() email: string;
  @Exclude() password: string; // 排除敏感字段
}

// 控制器中使用
@Get(':id')
@UseInterceptors(ClassSerializerInterceptor)
async findOne(@Param('id') id: string): Promise<UserResponseDto> {
  return this.service.findOne(id);
}

2. Repository 模式

隔离数据访问层，便于切换数据库和单元测试
// 定义接口
export interface IUserRepository {
  findById(id: string): Promise<User | null>;
  create(data: CreateUserDto): Promise<User>;
  update(id: string, data: UpdateUserDto): Promise<User>;
}

// Prisma 实现
@Injectable()
export class UserRepository implements IUserRepository {
  constructor(private prisma: PrismaService) {}

  async findById(id: string) {
    return this.prisma.user.findUnique({ where: { id } });
  }
}

// 测试时替换为 Mock
{
  provide: UserRepository,
  useClass: MockUserRepository,
}

3. 领域事件模式

解耦业务逻辑，异步处理副作用
@Injectable()
export class OrderService {
  constructor(private eventBus: EventBus) {}

  async createOrder(dto: CreateOrderDto) {
    const order = await this.repo.create(dto);

    // 发布事件，不关心谁处理
    this.eventBus.publish(new OrderCreatedEvent(order));

    return order;
  }
}

// 事件处理器（自动发送邮件、更新库存等）
@EventsHandler(OrderCreatedEvent)
export class OrderCreatedHandler {
  async handle(event: OrderCreatedEvent) {
    await this.email.sendOrderConfirmation(event.order);
    await this.inventory.decrement(event.order.items);
  }
}
