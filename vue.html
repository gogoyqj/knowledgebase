响应式原理：从 Proxy 到自动追踪

Vue 3 用 Proxy 替代了 Vue 2 的 Object.defineProperty， 实现了对任意嵌套对象的深度响应式追踪，无需递归遍历所有属性。

reactive()

深层响应式对象

reactive() 接受一个对象并返回其响应式代理。支持嵌套、数组、Map、Set 等任意数据结构。

JavaScriptreactive
import { reactive } from 'vue'

const state = reactive({
  user: { name: 'Alice', age: 28 },
  todos: ['学习 Vue 3', '写单元测试']
})

// ✅ 自动深度响应式，无需手动递归
state.user.name = 'Bob'       // 触发更新
state.todos.push('发布上线')  // 触发更新
warning
注意： reactive() 有以下限制：
1. 不能用于原始类型（string、number、boolean）
2. 不能替换整个对象（会丢失响应式）
3. 解构会丢失响应性（需用 toRefs()）
ref()

单一值响应式引用

ref() 接受任意值并返回一个响应式对象，通过 .value 访问内部值。适合原始类型和需要整体替换的场景。

JavaScriptref
import { ref } from 'vue'

const count = ref(0)
const user = ref({ name: 'Alice' })

// 在 JS 中需要 .value
count.value++                   // 触发更新
user.value = { name: 'Bob' } // ✅ 可以整体替换

// 在模板中自动解包，无需 .value
// <template><p>{{ count }}</p></template>
源码解析

Proxy 如何工作？

JavaScript简化版源码
function reactive(target) {
  return new Proxy(target, {
    get(target, key, receiver) {
      // 1. 收集依赖：记录哪个 effect 依赖了这个属性
      track(target, key)
      const result = Reflect.get(target, key, receiver)
      // 2. 深层代理：如果值是对象，递归代理
      if (Object.isObj(result)) return reactive(result)
      return result
    },
    set(target, key, value, receiver) {
      const ok = Reflect.set(target, key, value, receiver)
      // 3. 触发更新：通知所有依赖该属性的 effect 重新执行
      trigger(target, key)
      return ok
    }
  })
}

// 依赖存储结构：WeakMap<target, Map<key, Set<effect>>>
computed()

缓存计算属性

computed() 基于响应式依赖自动缓存，依赖不变则不重新计算。内部使用 dirty 标记实现惰性求值。

JavaScriptcomputed
import { ref, computed } from 'vue'

const firstName = ref('John')
const lastName = ref('Doe')

// 只读 computed
const fullName = computed(() => firstName.value + ' ' + lastName.value)

// 可写 computed（getter + setter）
const fullNameWritable = computed({
  get: () => firstName.value + ' ' + lastName.value,
  set: (val) => {
    [firstName.value, lastName.value] = val.split(' ')
  }
})
lightbulb
最佳实践： 在模板中直接使用 fullName，不要写成 fullName.value——模板自动解包 ref。

JavaScriptwatch vs watchEffect
import { ref, watch, watchEffect } from 'vue'

const keyword = ref('')
const page = ref(1)

// watch：显式侦听，可获取旧值
watch(keyword, (newVal, oldVal) => {
  console.log(`搜索词从 "${oldVal}" 变为 "${newVal}"`)
  page.value = 1 // 重置分页
})

// watch：侦听多个源
watch([keyword, page], ([kw, p]) => {
  fetchData(kw, p)
})

// watchEffect：自动追踪依赖
watchEffect(() => {
  document.title = `搜索: ${keyword.value} | 第${page.value}页`
})

shallow 与 toRef 系列

JavaScript性能技巧
import { shallowRef, triggerRef, toRefs } from 'vue'

// shallowRef：适用于大型列表
const bigList = shallowRef(generateThousandItems())
bigList.value = [...bigList.value, newItem]  // ✅ 触发更新
bigList.value[0].name = 'changed'             // ❌ 不触发（需手动）
triggerRef(bigList)                          // ✅ 手动触发

// toRefs：解构不丢失响应式
const state = reactive({ x: 1, y: 2 })
const { x, y } = toRefs(state)  // x 和 y 都是 ref
x.value++  // ✅ 原对象同步更新

Composition API：逻辑复用的革命

Composition API 用 函数组合 替代 Options API 的 选项合并， 让同一功能的逻辑集中在一处，而非分散在 data、methods、computed、watch 中。

const { count, double, increment } = useCounter()
const { data, loading } = useFetch('/api/users')
</script>

Composable 函数（Hooks）实战

Composable 是 Vue 3 逻辑复用的核心机制。以 use 开头命名，封装有状态的逻辑， 可在任意组件中组合使用。

示例

useCounter — 基础 Composable

JavaScriptcomposables/useCounter.ts
import { ref, computed } from 'vue'

export function useCounter(initialValue = 0, options = {}) {
  const { min = -Infinity, max = Infinity, step = 1 } = options

  const count = ref(initialValue)
  const doubleCount = computed(() => count.value * 2)

  function increment() {
    count.value = Math.min(count.value + step, max)
  }
  function decrement() {
    count.value = Math.max(count.value - step, min)
  }
  function reset() { count.value = initialValue }

  return { count, doubleCount, increment, decrement, reset }
}

// 使用：每调用一次创建独立状态
// const { count, increment } = useCounter(0, { min: 0, max: 10 })
实战

useFetch — 数据请求

JavaScriptcomposables/useFetch.ts
import { ref, watchEffect, onUnmounted } from 'vue'

export function useFetch<T>(url: Ref<string> | string) {
  const data = ref<T | null>(null) as Ref<T>
  const error = ref<Error | null>(null)
  const loading = ref(false)
  let controller: AbortController | null = null

  async function fetchData(target: string) {
    controller?.abort()
    controller = new AbortController()
    loading.value = true
    error.value = null
    try {
      const res = await fetch(target, { signal: controller.signal })
      data.value = await res.json()
    } catch (e) {
      if (e instanceof Error && e.name !== 'AbortError') error.value = e
    } finally {
      loading.value = false
    }
  }

  watchEffect(() => fetchData(typeof url === 'string' ? url : url.value))
  onUnmounted(() => controller?.abort())

  return { data, error, loading }
}
持久化

useLocalStorage — 状态持久化

JavaScriptcomposables/useLocalStorage.ts
import { ref, watch } from 'vue'

export function useLocalStorage<T>(key: string, defaultValue: T) {
  const stored = localStorage.getItem(key)
  const data = ref<T>(
    stored ? JSON.parse(stored) : defaultValue
  )

  watch(data, (val) => {
    localStorage.setItem(key, JSON.stringify(val))
  }, { deep: true })

  return data
}

// 使用：自动同步到 localStorage
// const theme = useLocalStorage('theme', 'light')
DOM

useEventListener — 自动清理

JavaScriptcomposables/useEventListener.ts
import { onMounted, onUnmounted, isRef, watch } from 'vue'

export function useEventListener(
  target: EventTarget | Ref<EventTarget | null>,
  event: string,
  handler: EventListener,
  options?: AddEventListenerOptions
) {
  function attach(el: EventTarget) {
    el.addEventListener(event, handler, options)
  }
  function detach(el: EventTarget) {
    el.removeEventListener(event, handler, options)
  }

  if (isRef(target)) {
    watch(target, (newEl, oldEl) => {
      oldEl && detach(oldEl)
      newEl && attach(newEl)
    }, { immediate: true })
  } else {
    onMounted(() => attach(target))
  }
  onUnmounted(() => {
    if (!isRef(target)) detach(target)
  })
}

// 使用
// useEventListener(window, 'scroll', onScroll)

最佳实践与常见陷阱

✅ 推荐

Composable 设计原则

  • 始终以 use* 命名：让 composable 一目了然
  • 返回 ref 而非 reactive：方便调用方解构不丢失响应式
  • 处理边界情况：空值、加载态、错误态都要考虑
  • 清理副作用：在 onUnmounted 中清理定时器、事件监听、WebSocket
  • 支持 ref 参数：用 isRef() + watch 让参数可以是响应式的
  • 避免副作用在 composable 外泄漏：不要修改全局状态，除非明确设计
⚠️ 陷阱

响应式丢失问题

JavaScript解构陷阱
const state = reactive({ x: 1, y: 2 })

// ❌ 错误：解构后丢失响应式
let { x, y } = state
x++  // 不触发更新！

// ✅ 正确：用 toRefs 保持引用
const { x, y } = toRefs(state)
x.value++  // ✅ 触发更新

// ✅ 或直接用 ref 包裹整个对象
const state2 = ref({ x: 1, y: 2 })
const { x, y } = toRefs(state2.value)
⚠️ 陷阱

响应式数据替换

JavaScript替换陷阱
let obj = reactive({ count: 0 })

// ❌ 错误：重新赋值变量会丢失响应式
obj = { count: 1 }  // 原响应式断开

// ✅ 正确：修改属性而非替换
obj.count = 1

// ✅ 或使用 ref（推荐）
const obj2 = ref({ count: 0 })
obj2.value = { count: 1 }  // ✅ ref 整体替换没问题
⚠️ 陷阱

watch 中的异步操作

JavaScriptwatch 常见错误
const keyword = ref('')

// ❌ 错误：异步回调中无法自动跟踪依赖
watch(keyword, async (val) => {
  const res = await fetch(`/api?q=${val}`)
  // 如果这里读取了其他 ref，它们的变化不会被追踪
})

// ✅ 正确：在同步部分读取所有响应式数据
watch(keyword, async (val) => {
  const baseUrl = apiUrl.value  // 同步读取
  const res = await fetch(`${baseUrl}?q=${val}`)
})

Provide / Inject 与跨层通信

provide / inject 让祖先组件向所有后代注入依赖，无需逐层传递 props。 配合 ref 或 reactive 可以实现响应式跨层通信。

跨层通信

provide / inject 完整示例

JavaScriptThemeContext 示例
// ─── 祖先组件：提供主题 ───
<script setup>
import { ref, provide } from 'vue'

const theme = ref('light')

function toggleTheme() {
  theme.value = theme.value === 'light' ? 'dark' : 'light'
}

// 提供响应式数据 + 方法
provide('theme', { theme, toggleTheme })
</script>

// ─── 后代组件（任意深度）：注入使用 ───
<script setup>
import { inject } from 'vue'

// 注入带默认值
const { theme, toggleTheme } = inject('theme', {
  theme: ref('light'),
  toggleTheme: () => {}
})
</script>

<!-- 模板中使用 -->
<template>
  <button @click="toggleTheme">
    当前主题：{{ theme }}
  </button>
</template>
lightbulb
何时用 provide/inject vs Pinia？
provide/inject 适合局部子树的依赖注入（如主题、表单上下文）。 全局共享状态、跨模块通信用 Pinia 更合适。
类型安全

TypeScript 类型化 Provide/Inject

TypeScript类型安全注入
// 定义注入键的类型
import { InjectionKey, Ref } from 'vue'

interface ThemeContext {
  theme: Ref<'light' | 'dark'>
  toggleTheme(): void
}

export const ThemeKey: InjectionKey<ThemeContext> = Symbol('theme')

// 父组件 provide
provide(ThemeKey, { theme, toggleTheme })

// 子组件 inject（类型安全）
const { theme } = inject(ThemeKey)  // 类型自动推断为 ThemeContext
