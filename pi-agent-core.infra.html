Purpose

A stateful LLM agent runtime that orchestrates multi-turn conversations with tool execution. Built on top of @pi-ai, it adds lifecycle management, message queuing, event subscription, tool hooks, and degenerate output detection.

Two-layer design: High-level Agent class wraps low-level stateless agentLoop functions. The loop is pure and functional; the class adds state, queues, and lifecycle.

High-Level API

Agent class — stateful wrapper with lifecycle management, event subscription, message queuing (steering + follow-up), and abort coordination.

Low-Level API

agentLoop() / agentLoopContinue() — stateless functions returning EventStream<AgentEvent>. No state management, no queuing — pure loop logic.

agent.ts — Stateful Agent Wrapper

const agent = new Agent({
  streamFn,           // LLM streaming function
  convertToLlm,       // AgentMessage[] → Message[] bridge
  transformContext,    // optional context pruning/compaction
  tools,              // AgentTool[] with execute handlers
  systemPrompt,       // string | () => string (dynamic)
  apiKey,             // string | () => Promise<string> (expiring tokens)
  getSteeringMessages,// async queue drain during tool execution
  getFollowUpMessages,// async queue drain after turn completion
  getContinuationMessages, // auto-continue after tool results
  shouldStopAfterTurn,
  shouldStopBeforeTurn,
  beforeToolCall,      // pre-execution hook (can block)
  afterToolCall,       // post-execution hook (can override)
})

State Ownership

  • Creates and manages MutableAgentState
  • Defensive copying on assignment (copy-on-write)
  • Public read: systemPrompt, model, thinkingLevel, serviceTier
  • Runtime read-only: isStreaming, streamingMessage, pendingToolCalls, errorMessage

Message Queues

  • Steering queue — drained during tool execution; injects user guidance mid-turn
  • Follow-up queue — drained after turn completion; handles async user input
  • Two drain modes: "all" (batch) or "one-at-a-time" (sequential)
  • steer(msg) / followUp(msg) — public queue methods

Run Lifecycle

  • prompt(message) — start new conversation turn
  • continue() — resume from current context
  • Both delegate to runWithLifecycle()
  • Creates AbortController, sets isStreaming
  • Concurrency guard: one active run at a time
  • abort() — cancel current run

Error Recovery

  • handleRunFailure() synthesizes error AssistantMessage
  • Emits lifecycle events even on unexpected failures
  • Errors never crash the agent — encoded in state

Loop Structure

// Outer loop: follow-up / continuation polling
while (hasFollowUps || hasContinuation) {
  // Inner loop: tool calls + steering injection
  while (hasToolCalls || hasSteeringMessages) {
    streamAssistantResponse()     // transformContext → convertToLlm → streamFn
    executeToolCalls()             // prepare → beforeToolCall → execute → afterToolCall
    drainSteeringMessages()        // inject queued steering input
  }
  drainFollowUpMessages()          // process follow-up queue
  checkContinuation()              // getContinuationMessages()
}

// Termination conditions:
//   - No more tool calls
//   - No steering messages
//   - No follow-ups
//   - No continuations
//   - shouldStopAfterTurn / shouldStopBeforeTurn triggers

AgentEvent — 11 Event Types

EventCategoryDescription
agent_start Lifecycle Agent run begins
agent_end Lifecycle Terminal event — run becomes idle after all listeners settle
turn_start Turn New LLM turn begins (after tool results)
turn_end Turn LLM turn completes
message_start Message Assistant message streaming begins
message_update Message Content delta received (text, thinking, tool call)
message_end Message Assistant message complete
tool_execution_start Tool Tool call begins execution
tool_execution_update Tool Tool execution progress update
tool_execution_end Tool Tool execution complete (emitted in completion order)
Listeners are awaited in registration order. agent_end is the terminal event, but the run only becomes idle after all agent_end listeners settle. Listeners receive the abort signal for cooperative cancellation.

Event Processing in Agent

processEvents(event) {
  // 1. Reduce internal state from each loop event
  updateStreamingMessage(event)
  updatePendingToolCalls(event)
  updateErrorMessage(event)

  // 2. Fan out to all subscribers
  for (const listener of subscribers) {
    await listener(event)
  }
}

  // From pi-ai Tool
  name: string

  // Agent extensions
  label: string              // UI display name

}

AgentToolResult

interface AgentToolResult<T> {
  content: string | ImageContent[]  // for LLM
  details?: T                      // for UI
  terminate?: boolean               // stop hint
}

terminate hint: when all tools in a batch agree to terminate, the agent stops after that batch.

beforeToolCall Hook

  • Called before tool execution
  • Can block execution (return false / reason)
  • Context: tool name, arguments, abort signal

afterToolCall Hook

  • Called after tool execution
  • Can override result content, error status, termination hint
  • Context: tool name, original result, arguments

Execution Modes

ModeBehaviorWhen Used

Sequential One tool at a time, in order Any tool with executionMode: "sequential" forces entire batch sequential

proxy.ts — Server-Side Proxy Adapter

streamProxy(options: ProxyStreamOptions) => AssistantMessageEventStream

interface ProxyStreamOptions {
  url: string
  headers?: Record<string, string>
  body: object
  signal?: AbortSignal
}

For browser apps routing LLM calls through a backend server. The server strips partial fields from SSE delta events to reduce bandwidth; the client reconstructs the partial message locally.

  • SSE parsing with fetch() + ReadableStream
  • Abort signal propagation
  • Error recovery and reconnection hints
  • Client-side partial message reconstruction
warning Repetition Guard

repetition-guard.ts — Degenerate Output Detection

Detects periodic repetition in LLM output tails using a KMP failure-function algorithm combined with trigram novelty scoring. Can interrupt streaming mid-response.

Core Algorithm

  • detectPeriodicTail() — KMP-based periodic pattern detection in text tail
  • hasTailRepetition() — full check with normalization

Streaming Integration

  • shouldInterruptForTailRepetition() — stride-aware streaming check
  • wrapStreamWithTailRepetitionGuard() — wraps event stream, injects synthetic errors

Configuration

  • enabled — toggle
  • minChars — minimum text to start checking
  • checkEveryChars — stride interval
  • windowChars — tail window size
  • maxUnitChars — max repeat unit
  • minRepeats — threshold
  • normalizeWhitespace
  • normalizePunctuation
Note: repetition-guard.ts is NOT re-exported from index.ts. Its functions are imported directly in tests but not part of the public barrel API.
