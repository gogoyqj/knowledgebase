MP4 文件格式概述

MP4（MPEG-4 Part 14）基于 ISO Base Media File Format (ISOBMFF)，是一种容器格式，用于存储视频、音频、字幕和元数据。其核心设计思想是将文件组织为一系列嵌套的 Box（也称 Atom）。

lightbulb
关键特性：MP4 的 Box 结构允许随机访问——播放器可以跳转到任意时间点，因为 moov Box 中包含了所有采样的位置索引。这也是 MP4 适合流式播放的基础。

支持的编码

H.264 / AVC H.265 / HEVC AV1 AAC Opus MP3

相关规范

ISO 14496-12 ISO 14496-14 QuickTime (.mov) 3GP / M4A / M4V

Box 结构详解

每个 Box 由 Header（8 字节）+ Body（变长）组成：

┌──────────────────────────────────────────────┐ │ Box Header (8 bytes) │ │ ┌──────────────────┬──────────────────────┐ │ │ │ size (4 bytes) │ type (4 bytes) │ │ │ │ uint32 │ FourCC (ASCII) │ │ │ └──────────────────┴──────────────────────┘ │ │ │ │ Box Body (size - 8 bytes) │ │ ┌────────────────────────────────────────┐ │ │ │ data ... │ │ │ └────────────────────────────────────────┘ │ └──────────────────────────────────────────────┘ Extended size: 当 size == 1 时，后续 8 字节为真实大小（共 16 字节 header） Terminal: 当 size == 0 时，Box 延伸到文件末尾
labelBox Header 字段
字段大小类型说明
size 4 bytes uint32 Box 总大小（含 header），若为 1 则使用 extended size（后续 8 字节）
type 4 bytes FourCC Box 类型标识，如 ftyp、moov、mdat
extended_size 8 bytes uint64 仅当 size==1 时存在，表示大于 4GB 的 Box
categoryFull Box（版本化）

部分 Box 继承自 Full Box，在 header 后额外包含 1 字节版本 + 3 字节标志位：

┌──────────────────────────────────────────────┐ │ Full Box Header │ │ ┌──────────┬──────────┬─────────┬─────────┐ │ │ │ size │ type │ version │ flags │ │ │ │ 4B │ 4B │ 1B │ 3B │ │ │ └──────────┴──────────┴─────────┴─────────┘ │ │ version: 0 或 1 │ │ flags: 各 Box 自定义的标志位 │ └──────────────────────────────────────────────┘

stbl — 采样表（核心）

stbl（Sample Table）是 MP4 最核心的 Box，它告诉播放器：每个采样在哪里、多大、什么时间播放。没有它，mdat 就是一堆无意义的字节。

movie_filterstsd — 采样描述

定义编解码器类型和配置，如 avc1（H.264）内含 avcC（SPS/PPS 参数集）。

stsd └── avc1 # H.264 视频采样描述 ├── width, height ├── compressorName └── avcC # AVC Decoder Configuration ├── configurationVersion ├── profileIndication ├── levelIndication ├── SPS (Sequence Parameter Set) └── PPS (Picture Parameter Set)
timerstts — Decoding Time-to-Sample

将采样索引映射到解码时间戳。用 run-length 编码压缩：

字段说明
sample_count连续相同 duration 的采样数
sample_delta每个采样的时间增量（timescale 单位）
calculate
计算总时长：将所有 stts 条目的 sample_count × sample_delta 求和，再除以 mdhd 的 timescale，得到秒数。
grid_onstsc — Sample-to-Chunk 映射

采样被组织为 chunk，每个 chunk 包含若干采样。stsc 记录每个 chunk 的采样数：

字段说明
first_chunk当前条目起始的 chunk 编号
samples_per_chunk该范围内每个 chunk 的采样数
sample_description_index使用的 stsd 条目索引
aspect_ratiostsz — 采样大小

记录每个采样的字节大小。若 sample_size != 0，所有采样等大；否则逐个列出：

stsz ├── sample_size: 0 # 0 = 各采样大小不同 ├── sample_count: 150 # 总采样数 └── entry_size[]: [12345, 8901, 15678, ...] # 每个采样的字节数
my_locationstco / co64 — chunk 偏移

记录每个 chunk 在文件中的绝对字节偏移。播放器结合 stsc + stsz + stco 即可定位任意采样：

定位采样 #N 的流程: 1. stss → N 是不是关键帧？（用于 seek） 2. stts → 前 N-1 个 delta 求和 → decode time 3. ctts → composition offset → display time 4. stsc → 采样 #N 属于哪个 chunk？ 5. stco → chunk 在文件中的偏移 6. stsc → 该 chunk 从第几个采样开始？ 7. stsz → 累加前面采样的大小 → chunk 内偏移 8. 读取 stsz[N] 字节 → 得到采样数据
key
这就是 MP4 支持随机 Seek 的秘密：所有索引信息都在 moov 中预计算好，播放器可以跳转到任意采样而无需线性扫描。

mdat — 媒体数据

mdat 存储所有轨道的实际采样数据，以连续字节流的形式排列。它本身没有任何结构——完全依赖 moov 中的采样表来解释。

┌──────────────────────────────────────────────────────────────┐ │ mdat │ │ ┌─────────────────────────────────────────────────────────┐ │ │ │ [video chunk 0] [audio chunk 0] [video chunk 1] ... │ │ │ │ │ │ │ │ 视频采样 = NAL Units (H.264) / OBU (AV1) │ │ │ │ 音频采样 = AAC Frames / PCM / Opus Frames │ │ │ └─────────────────────────────────────────────────────────┘ │ └──────────────────────────────────────────────────────────────┘ H.264 NAL Unit 结构: ┌──────────────┬──────────────┬─────────────────────────────┐ │ start_code │ NAL header │ NAL payload │ │ 00 00 00 01 │ 1B (type) │ SPS/PPS/IDR/SLICE/... │ └──────────────┴──────────────┴─────────────────────────────┘
warning
重要：普通 MP4 的 mdat 中，H.264 使用 AVCC 格式（4字节长度前缀），而非 Annex B（start code）。播放器需要根据 avcC 中的 SPS/PPS 初始化解码器。

MSE — Media Source Extensions

Media Source Extensions (MSE) 是浏览器 API，允许 JavaScript 动态向 <video> 元素推送媒体数据。它是所有现代流媒体方案（HLS.js、Dash.js、自定义流）的基础。

javascript — MSE StreamPlayer content_copy 
class StreamPlayer {
  constructor(videoElement) {
    this.video = videoElement;
    this.mediaSource = new MediaSource();
    this.video.src = URL.createObjectURL(this.mediaSource);
    this.sourceBuffer = null;
    this.queue = [];

    this.mediaSource.addEventListener('sourceopen', () => {
      this.initSourceBuffer();
    });
  }

  initSourceBuffer() {
    const mimeType = 'video/mp4; codecs="avc1.4D401E, mp4a.40.2"';

    if (!MediaSource.isTypeSupported(mimeType)) {
      console.error('不支持的编码格式:', mimeType);
      return;
    }

    this.sourceBuffer = this.mediaSource.addSourceBuffer(mimeType);
    this.sourceBuffer.addEventListener('updateend', () => {
      this.processQueue();
    });
  }

  // 追加数据（自动排队）
  appendBuffer(data) {
    if (this.sourceBuffer.updating) {
      this.queue.push(data);
    } else {
      this.sourceBuffer.appendBuffer(data);
    }
  }

  // 处理排队的数据
  processQueue() {
    if (this.queue.length > 0 && !this.sourceBuffer.updating) {
      this.sourceBuffer.appendBuffer(this.queue.shift());
    }
  }

  // 结束流
  endStream() {
    if (this.mediaSource.readyState === 'open'
        && !this.sourceBuffer.updating
        && this.queue.length === 0) {
      this.mediaSource.endOfStream();
    }
  }
}

async function streamLoad(url, player) {
  const response = await fetch(url);
  const reader = response.body.getReader();

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;

    // value 是 Uint8Array，直接追加
    player.appendBuffer(value);
  }

  player.endStream();
}

javascript — 分段请求 content_copy 
async function loadByRange(url, player, chunkSize = 1024 * 1024) {
  // 先获取文件大小
  const head = await fetch(url, { method: 'HEAD' });
  const totalSize = parseInt(head.headers.get('content-length'));

  // 分段请求
  for (let start = 0; start < totalSize; start += chunkSize) {
    const end = Math.min(start + chunkSize - 1, totalSize - 1);

    const resp = await fetch(url, {
      headers: {
        'Range': `bytes=${start}-${end}`
      }
    });

    const buffer = await resp.arrayBuffer();
    player.appendBuffer(buffer);
  }

  player.endStream();
}

javascript — AdvancedPlayer content_copy 
class AdvancedPlayer {
  constructor(video, url) {
    this.video = video;
    this.url = url;
    this.ms = new MediaSource();
    this.video.src = URL.createObjectURL(this.ms);
    this.loadedRanges = [];  // 已加载的字节范围

    this.ms.addEventListener('sourceopen', () => this.onOpen());
    video.addEventListener('seeking', () => this.onSeek());
  }

  async onOpen() {
    this.sb = this.ms.addSourceBuffer('video/mp4; codecs="avc1.4D401E"');
    await this.loadRange(0, 1024 * 1024); // 先加载 1MB
  }

  async loadRange(start, end) {
    // 检查是否已加载
    if (this.isRangeLoaded(start, end)) return;

    const resp = await fetch(this.url, {
      headers: { 'Range': `bytes=${start}-${end}` }
    });

    const data = await resp.arrayBuffer();

    await new Promise(resolve => {
      this.sb.addEventListener('updateend', resolve, { once: true });
      this.sb.appendBuffer(data);
    });

    this.loadedRanges.push({ start, end });
  }

  isRangeLoaded(start, end) {
    return this.loadedRanges.some(
      r => r.start <= start && r.end >= end
    );
  }

  async onSeek() {
    // 根据 seek 时间计算需要的字节范围
    const time = this.video.currentTime;
    const range = this.timeToByteRange(time);
    await this.loadRange(range.start, range.end);
  }
}

ffmpeg -i input.mp4 -c copy -movflags +faststart output.mp4

# 3. 生成 HLS 分片（.m3u8 + .ts）
ffmpeg -i input.mp4 -c copy \
  -hls_time 4 -hls_list_size 0 \
  -hls_segment_filename "seg_%03d.ts" \
  playlist.m3u8

# 4. 生成 DASH 分片（.mpd + .m4s）
ffmpeg -i input.mp4 -c copy \
  -f dash -seg_duration 4 \
  -adaptation_sets "id=0,streams=v id=1,streams=a" \
  manifest.mpd

# 5. 仅转换视频轨道为 H.264，音频保持原样
ffmpeg -i input.mkv \
  -c:v libx264 -preset medium -crf 23 \
  -c:a copy \
  -movflags +faststart \
