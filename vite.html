Vite 是什么？

Vite（法语"快"的意思）是下一代前端构建工具。它利用浏览器原生 ESM 实现极速开发启动， 生产环境使用 Rollup 打包，兼顾开发体验与生产优化。

lightbulb
Vite 的核心理念：开发时不打包。传统工具（Webpack）在启动时需要构建完整的依赖图，而 Vite 只在浏览器请求时才按需编译，冷启动速度提升 10-100 倍。
compare_arrows

Vite vs Webpack 架构对比

📦 Webpack（打包优先）

  • 启动时构建完整依赖图
  • 所有模块打包成 bundle
  • HMR 需重新构建受影响的 chunk
  • 启动时间随项目规模线性增长

⚡ Vite（按需编译）

  • 启动时只预构建 node_modules 依赖
  • 源码通过 ESM 按需加载
  • HMR 只更新单个模块，与项目规模无关
  • 启动时间几乎恒定（毫秒级）

// vite.config.ts — 完整配置示例
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { resolve } from 'path'

export default defineConfig({
  // 项目根目录
  root: '.',

  // 开发服务器配置
  server: {
    port: 3000,
    open: true,
    proxy: {
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true
      }
    }
  },

  // 构建配置
  build: {
    outDir: 'dist',
    minify: 'esbuild',
    rollupOptions: {
      input: {
        main: resolve(__dirname, 'index.html')
      },
      output: {
        manualChunks: {
          vendor: ['vue', 'vue-router']
        }
      }
    }
  },

  // 插件
  plugins: [
    vue()
  ],

  // 路径别名
  resolve: {
    alias: {
      '@': resolve(__dirname, 'src')
    }
  }
})

开发模式生命周期

Vite 开发服务器启动后，浏览器通过原生 ESM 请求模块。每个请求经过 Vite 的中间件管道处理。

1. 读取配置

解析 vite.config.ts → 合并默认配置 → 解析环境变量

2. 创建插件容器

实例化所有插件 → 调用 config / configResolved 钩子

3. 依赖预构建

扫描 node_modules → esbuild 打包 CJS/UMD 为 ESM → 缓存到 node_modules/.vite

4. 启动 Dev Server

创建 Koa 服务器 → 注册中间件 → 启动 WebSocket（HMR）→ 调用 configureServer 钩子

5. 按需编译

浏览器请求模块 → 匹配插件钩子 → transform / load → 返回编译结果

6. HMR 热更新

文件变化 → chokidar 监听 → 分析模块图 → 通过 WebSocket 推送更新

build

生产构建生命周期

生产环境 vite build 使用 Rollup 进行打包，流程与开发模式完全不同。

1. 读取配置 + 插件初始化

解析配置 → 调用 config / configResolved 钩子

2. Rollup 打包

从入口开始 → resolveId / load / transform 处理每个模块 → 构建模块图 → Tree Shaking

3. 代码生成

Chunk 分割 → Code Splitting → 生成 AST → 输出代码

4. 资源优化

代码压缩（esbuild/terser）→ CSS 优化 → 图片优化 → 生成 hash 文件名

5. 输出文件

调用 generateBundle / writeBundle 钩子 → 写入 dist 目录

extension

Vite Plugin 是什么？

Vite 插件基于 Rollup 插件接口构建，扩展了 Vite 特有的钩子。 一个 Vite 插件就是一个返回插件配置对象的函数。

lightbulb
Vite 插件 = Rollup 插件接口 + Vite 独有钩子。这意味着一个 Vite 插件可以同时在开发和生产环境工作，且大部分 Rollup 插件可以直接在 Vite 中使用。
architecture

插件基本结构

一个 Vite 插件是一个函数，返回一个包含钩子的对象：

// Vite 插件基本模板
import type { Plugin } from 'vite'

export default function myPlugin(): Plugin {
  return {
    // 插件名称（用于日志和调试）
    name: 'vite-plugin-my',

    // 应用顺序：'pre' | 'post' | 默认
    enforce: 'pre',

    // 只在特定环境生效
    apply: 'build',  // 'build' | 'serve'

    // ─── 配置钩子 ───
    config(config, { command }) {
      // 修改 Vite 配置
      return {
        define: {
          __APP_VERSION__: JSON.stringify('1.0.0')
        }
      }
    },

    // ─── 服务器钩子 ───
    configureServer(server) {
      // 自定义开发服务器中间件
      server.middlewares.use((req, res, next) => {
        next()
      })
    },

    // ─── 转换钩子 ───
    transform(code, id) {
      // 转换模块内容
      return code
    },

    // ─── 构建钩子 ───
    generateBundle(options, bundle) {
      // 处理输出 bundle
    }
  }
}

实战：环境变量注入插件

一个实用的插件，自动注入构建信息到全局变量：

import type { Plugin } from 'vite'

export default function buildInfoPlugin(): Plugin {
  return {
    name: 'vite-plugin-build-info',
    enforce: 'pre',

    config() {
      return {
        define: {
          __BUILD_TIME__: JSON.stringify(new Date().toISOString()),
          __BUILD_HASH__: JSON.stringify(
            Math.random().toString(36).substring(2, 10)
          ),
          __NODE_ENV__: JSON.stringify(process.env.NODE_ENV)
        }
      }
    }
  }
}

实战：虚拟模块插件

创建一个虚拟模块，运行时动态生成内容（不对应真实文件）：

import type { Plugin } from 'vite'

export default function virtualModulePlugin(): Plugin {
  const virtualModuleId = 'virtual:config'
  const resolvedVirtualModuleId = '\0' + virtualModuleId

  return {
    name: 'vite-plugin-virtual-config',

    // 1. 解析虚拟模块 ID
    resolveId(id) {
      if (id === virtualModuleId) {
        return resolvedVirtualModuleId
      }
    },

    // 2. 加载虚拟模块内容
    load(id) {
      if (id === resolvedVirtualModuleId) {
        return `
          export const config = {
            apiUrl: '${process.env.API_URL || "http://localhost:3000"}',
            version: '${process.env.npm_package_version || "0.0.0"}',
            debug: ${process.env.NODE_ENV !== 'production'}
          }
        `
      }
    }
  }
}

// 使用：import { config } from 'virtual:config'

实战：代码转换插件

在模块加载时转换代码内容（类似 Loader 的功能）：

import type { Plugin } from 'vite'

export default function svgComponentPlugin(): Plugin {
  return {
    name: 'vite-plugin-svg-component',
    enforce: 'pre',

    // 转换 .svg?component 导入为 Vue/React 组件
    transform(code, id) {
      if (!id.endsWith('.svg?component')) return

      // 读取 SVG 内容
      const svgPath = id.replace('?component', '')
      const fs = require('fs')
      const svgContent = fs.readFileSync(svgPath, 'utf-8')

      // 转为 Vue 组件
      return `
        <template>
          ${svgContent}
        </template>
        <script>
        export default { name: 'SvgIcon' }
        </script>
      `
    }
  }
}

实战：开发服务器中间件插件

通过 configureServer 钩子扩展开发服务器：

import type { Plugin } from 'vite'

export default function apiMockPlugin(): Plugin {
  return {
    name: 'vite-plugin-api-mock',
    apply: 'serve',  // 仅开发环境

    configureServer(server) {
      // 在 Vite 内部中间件之前注入
      server.middlewares.use((req, res, next) => {
        // 拦截 /api/mock/* 请求
        if (req.url?.startsWith('/api/mock/')) {
          const mockName = req.url.replace('/api/mock/', '')

          // 返回模拟数据
          res.setHeader('Content-Type', 'application/json')
          res.end(JSON.stringify({
            code: 200,
            data: { mock: true, name: mockName },
            message: 'Mock response'
          }))
          return
        }
        next()
      })
    }
  }
}

实战：HTML 转换插件

使用 transformIndexHtml 钩子修改 HTML 内容：

import type { Plugin } from 'vite'

export default function htmlMetaPlugin(options: {
  title?: string
  description?: string
}): Plugin {
  return {
    name: 'vite-plugin-html-meta',

    // 转换 index.html
    transformIndexHtml(html) {
      return html.replace(
        '<head>',
        `<head>
          <meta name="description" content="${options.description || ''}">
          <meta property="og:title" content="${options.title || ''}">
          <meta property="og:description" content="${options.description || ''}">
        `
      )
    }
  }
}

// 使用
htmlMetaPlugin({
  title: 'My App',
  description: 'A modern web application'
})

Vite 插件钩子总览

Vite 插件钩子分为三类：通用钩子（Rollup 兼容）、构建钩子（仅构建）、服务器钩子（仅开发）。

settings

通用钩子（开发 + 构建）

// 通用钩子 — 开发和构建环境都会调用

// ─── 配置阶段 ───
config(config, { command, mode })
  // 返回部分配置对象，深度合并到 Vite 配置中
  // command: 'serve' | 'build'

configResolved(config)
  // 配置解析完成后调用，可读取最终配置
  // 此时配置已合并，不可再修改

configureServer(server)        // ⭐ Vite 独有
  // 配置开发服务器，注入自定义中间件

configurePreviewServer(server)  // ⭐ Vite 独有
  // 配置预览服务器

// ─── 模块解析阶段 ───
resolveId(source, importer, options)
  // 自定义模块解析逻辑
  // 返回 ID 字符串表示接管解析
  // 返回 null 表示使用默认解析

load(id)
  // 自定义模块加载逻辑
  // 返回代码字符串表示接管加载

transform(code, id)
  // 转换模块代码
  // 返回转换后的代码或 { code, map }

// ─── 输出阶段 ───
buildStart(options)
  // 构建开始时调用

buildEnd(error)
  // 构建结束时调用（bundle 生成前）

generateBundle(options, bundle, isWrite)
  // bundle 生成后、写入前调用
  // 可修改、添加、删除 bundle 中的文件

writeBundle(options, bundle)
  // bundle 写入磁盘后调用

closeBundle()
  // 构建完全结束后调用
dns

Vite 独有钩子

// Vite 独有钩子 — 不在 Rollup 接口中

// ─── HTML 转换 ───
transformIndexHtml(html, ctx)
  // 转换 index.html
  // ctx: { path, filename, server?, bundle?, chunk? }
  // 可返回：修改后的 HTML | Tag 描述符数组 | void

// ─── HMR ───
handleHotUpdate(ctx)
  // 自定义 HMR 更新逻辑
  // ctx: { file, timestamp, modules, read, server }
  // 返回 HMR 模块数组表示接管更新
  // 返回空数组表示阻止更新

// ─── 环境变量 ───
transformIndexHtml  // 也可用于注入环境变量到 HTML

// ─── 开发服务器 ───
configureServer(server)
  // server.middlewares.use(...) — 注册中间件
  // server.ws.send(...) — 发送 WebSocket 消息
  // server.watcher — chokidar 文件监听实例

tips_and_updates

插件开发最佳实践

📌 命名规范

插件名称使用 vite-plugin-xxx 格式，便于 npm 搜索和社区发现。

🎯 enforce 控制顺序

'pre' 在核心插件前执行，'post' 在之后。默认在核心插件之间。

🔍 apply 限定环境

'serve' 仅开发，'build' 仅构建。避免不必要的插件逻辑。

⚡ 过滤文件

在 transform 中用 id.includes() 或正则过滤，避免处理无关文件影响性能。

🗺️ Source Map

transform 返回 { code, map } 以支持 Source Map 调试。

🧪 测试插件

使用 createServer() / build() API 编写集成测试。

Vite Plugin vs Webpack Plugin

📦 Webpack Plugin

  • 类 + apply(compiler) 方法
  • 通过 compiler.hooks.xxx.tap() 注册
  • 基于 Tapable 事件系统
  • 钩子数量多，粒度细
  • 需要理解 Compiler / Compilation

⚡ Vite Plugin

  • 函数返回配置对象
  • 钩子直接作为对象属性
  • 基于 Rollup 插件接口
  • 钩子更少，更直观
  • 兼容 Rollup 插件生态

Vite 让前端开发回归纯粹——快速启动、即时反馈、专注业务
