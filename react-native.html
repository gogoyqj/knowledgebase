React Native C++ Plugin 开发指南

从零构建一个使用 C++ 实现核心逻辑的 React Native 原生模块。涵盖 JSI、Bridge、Expo Modules、Nitro Modules 四种方案。

1. React Native 工作原理

核心思想：JavaScript 驱动原生 UI

React Native 的本质是用 JavaScript 编写业务逻辑，但渲染的是真正的原生控件（不是 WebView）。它通过一个桥接层让 JS 和 Native 互相通信。

三线程模型

┌─────────────────────────────────────────────────────────────────────────┐ │ React Native Thread Model │ │ │ │ ┌──────────────────┐ ┌──────────────────┐ ┌────────────────────┐ │ │ │ JS Thread │ │ Native Thread │ │ Shadow Thread │ │ │ │ │ │ │ │ (Yoga Layout) │ │ │ │ • React 逻辑 │ │ • 原生 UI 渲染 │ │ • Flexbox 布局计算│ │ │ │ • 业务代码 │ │ • 原生模块调用 │ │ • 样式解析 │ │ │ │ • 状态管理 │ │ • 事件处理 │ │ │ │ │ │ • JSI 调用 │ │ • 绘制到屏幕 │ │ │ │ │ └────────┬─────────┘ └────────┬─────────┘ └────────┬───────────┘ │ │ │ │ │ │ │ └──────────────────────┼──────────────────────┘ │ │ Communication Layer │ │ (Bridge / JSI / Fabric) │ └─────────────────────────────────────────────────────────────────────────┘
  • JS Thread：运行 Hermes 或 JavaScriptCore 引擎，执行 React 组件树的渲染逻辑、状态更新、事件回调
  • Native Thread（UI Thread）：负责原生 View 的创建、布局、绘制，以及触摸事件的分发
  • Shadow Thread：运行 Yoga（Facebook 的跨平台 Flexbox 引擎），计算布局树，将 JS 的 StyleSheet 转换为绝对坐标

渲染流程

JS: setState() → Virtual DOM Diff → Shadow Tree 布局 → Native View 更新 → 屏幕渲染
  1. JS 侧：React 执行 render，生成 Virtual DOM，diff 出变化
  2. 序列化传输：将 UI 操作指令序列化（旧架构 JSON，新架构 JSI 直传）
  3. Shadow Tree：Yoga 引擎计算 Flexbox 布局，得出每个 View 的位置和尺寸
  4. Native 侧：根据布局结果创建/更新真正的原生 UIView（iOS）或 ViewGroup（Android）
  5. 事件回传：用户触摸 → Native 捕获 → 序列化为事件 → JS 处理回调

关键区别：旧架构中 JS 和 Native 通过异步 Bridge（JSON 队列）通信，每帧最多传递一次消息。新架构通过 JSI 让 JS 直接调用 C++ 对象，实现同步、零拷贝通信，这是性能飞跃的关键。

3. 架构演进：Bridge → JSI

旧架构：Bridge（已废弃）

JS → JSON 序列化 Bridge Queue → JSON 反序列化 Native

问题：异步、有序列化开销、类型不安全、桥接成为性能瓶颈。

新架构：JSI（推荐）

JS → C++ 直调 JSI Runtime → 同步执行 C++ 实现

优势：同步、零拷贝、类型安全、无序列化。

  int height;
};

CircleResult drawCircle(int radius, uint32_t color);

}

CircleJSI.h — JSI 绑定声明

#pragma once
#include <jsi/jsi.h>
#include "CircleDrawer.h"

/**
 * 注册 __drawCircle 到 JS 全局。
 * JS 调用: const result = __drawCircle(100, 0xFF0000FF)
 */

}

CircleJSI.cpp — JSI 绑定实现

#include "CircleJSI.h"
using namespace facebook;

namespace circleplugin {

void installCircleJSI(jsi::Runtime &runtime) {
  // 创建 HostFunction，JS 侧作为全局函数调用
  auto drawCircleFunc = jsi::Function::createFromHostFunction(
    runtime,
    jsi::PropNameID::forAscii(runtime, "__drawCircle"),
    2, // 参数个数
    [](jsi::Runtime &rt,
       const jsi::Value &thisVal,
       const jsi::Value *args,
       size_t count) -> jsi::Value {

      // 参数校验
      if (count < 2) {
        throw jsi::JSError(rt, "__drawCircle requires 2 arguments");
      }

      int radius = static_cast<int>(args[0].asNumber());
      uint32_t color = static_cast<uint32_t>(args[1].asNumber());

      // 调用 C++ 核心
      auto result = drawCircle(radius, color);

      // 创建 ArrayBuffer（零拷贝或拷贝取决于平台）
      auto buffer = jsi::ArrayBuffer::createFromBytes(
        rt, result.pixels.data(), result.pixels.size()
      );

      // 返回 JS 对象
      auto obj = jsi::Object(rt);
      obj.setProperty(rt, "width", result.width);
      obj.setProperty(rt, "height", result.height);
      obj.setProperty(rt, "buffer", std::move(buffer));
      return obj;
    });

  // 注册到全局
  runtime.global().setProperty(runtime, "__drawCircle", std::move(drawCircleFunc));
}

}
JSI 核心 API：
• jsi::Function::createFromHostFunction() — 将 C++ lambda 包装为 JS 函数
• jsi::ArrayBuffer::createFromBytes() — 将 C++ 内存包装为 JS ArrayBuffer
• jsi::Object / jsi::Value — JS 对象的 C++ 表示
• throw jsi::JSError() — 抛出 JS 异常

6. JS 侧调用

类型声明

// NativeCirclePlugin.ts
export interface CircleResult {
  width: number;
  height: number;
  buffer: ArrayBuffer;
}

// 声明全局 JSI 函数
declare global {
  function __drawCircle(radius: number, color: number): CircleResult;
}

export function drawCircle(radius: number, color: number): CircleResult {
  if (typeof globalThis.__drawCircle !== 'function') {
    throw new Error('CirclePlugin JSI not initialized');
  }
  return globalThis.__drawCircle(radius, color);
}

7. 平台注册

iOS — ObjC++ 获取 Runtime

// CirclePlugin.mm
#import <React/RCTBridge+Private.h>
#include "../cpp/CircleJSI.h"

@implementation CirclePlugin

RCT_EXPORT_MODULE();

- (void)setBridge:(RCTBridge *)bridge {
  [super setBridge:bridge];
  dispatch_async(dispatch_get_main_queue(), ^{
    RCTCxxBridge *cxxBridge = (RCTCxxBridge *)self.bridge;
    jsi::Runtime *runtime = (jsi::Runtime *)cxxBridge.runtime;
    circleplugin::installCircleJSI(*runtime);  // 一行搞定
  });
}

@end

9. Expo Modules 推荐

Expo Modules 是目前最省事的方案：用 Swift/Kotlin 写模块，自动生成 JSI 绑定。

特点

  • 不需要手写 JNI / ObjC++ 桥接
  • 不需要手写 JSI 绑定
  • 用 Swift（iOS）/ Kotlin（Android）写原生代码
  • 自动生成 TypeScript 类型

示例

// Swift — iOS
import ExpoModulesCore

public class CircleModule: Module {
  public func definition() -> ModuleDefinition {
    Name("CirclePlugin")

    AsyncFunction("drawCircle") { (radius: Int, color: Double) -> [String: Any] in
      let result = drawCircle(radius: radius, color: UInt32(color))
      return [
        "width": result.width,
        "height": result.height,
        "data": Data(result.pixels).base64EncodedString()
      ]
    }
  }
}
// Kotlin — Android
import expo.modules.kotlin.modules.Module
import expo.modules.kotlin.modules.ModuleDefinition

class CircleModule : Module() {
  override fun definition() = ModuleDefinition {
    Name("CirclePlugin")

    AsyncFunction("drawCircle") { radius: Int, color: Double ->
      val result = drawCircle(radius, color.toUInt())
      mapOf(
        "width" to result.width,
        "height" to result.height,
        "data" to Base64.encodeToString(result.pixels, Base64.NO_WRAP)
      )
    }
  }
}
// TypeScript — 直接用，类型自动生成
import { requireNativeModule } from 'expo-modules-core'
const CirclePlugin = requireNativeModule('CirclePlugin')

const result = await CirclePlugin.drawCircle(100, 0xFF0000FF)
C++ 代码怎么用？ Expo Modules 支持 expo-modules-core 的 C++ 扩展，或者通过 expo-cpp 桥接。对于纯 C++ 库，可以在 Swift/Kotlin 层调用 C++（iOS 通过 ObjC++ 桥接，Android 通过 JNI）。

10. Nitro Modules Experimental

Nitro 是 Marc Rousavy（react-native-maps 作者）开发的下一代模块框架，基于 JSI + Codegen。

特点

  • 用 TypeScript 定义接口，自动生成 C++ / Swift / Kotlin 绑定
  • 比 Expo Modules 更底层，支持直接操作 C++ 对象
  • HybridObject 模式：JS 对象直接持有 C++ 对象引用

示例

// 1. TypeScript 定义 spec
// nitrogen.ts
import { HybridObject } from 'react-native-nitro-modules'

interface CircleSpec extends HybridObject {
  drawCircle(radius: number, color: number): ArrayBuffer
}
// 2. 运行 codegen，自动生成 C++ 绑定
$ npx nitro-codegen --platform ios android

// 生成:
//   HybridCircleSpec.hpp     ← C++ 抽象接口
//   HybridCircleSpec.cpp     ← JSI 绑定
//   HybridCircleSpec.swift   ← iOS 桥接
//   HybridCircleSpec.kt      ← Android 桥接
// 3. 实现 C++ 接口
class HybridCircle : public HybridCircleSpec {
public:
  jsi::ArrayBuffer drawCircle(double radius, double color) override {
    auto result = circleplugin::drawCircle((int)radius, (uint32_t)color);
    // 返回 ArrayBuffer，Nitro 自动处理内存管理
    return ArrayBufferWrapper(result.pixels);
  }
};
// 4. JS 侧使用
import { getNitroModule } from 'react-native-nitro-modules'

const circle = getNitroModule<CircleSpec>('Circle')
const buffer = circle.drawCircle(100, 0xFF0000FF)
Nitro vs Expo Modules：
• Nitro 更底层，适合需要直接操作 C++ 对象的场景
• Expo Modules 更高层，适合大部分业务模块
• Nitro 的 HybridObject 允许 JS 持有 C++ 对象生命周期
• Expo Modules 适合从 ObjC++/Java 迁移的项目

11. 什么时候该用 C++？

场景建议
简单逻辑（画个圆、字符串处理）Java / Swift 直接写，不需要 C++
已有 C++ 库（OpenCV、FFmpeg、SQLite）用 C++，避免重写
跨平台共享代码（iOS + Android + 桌面）用 C++，一份代码多端复用
性能密集型（音视频、物理模拟、ML）用 C++，性能优势明显
想绕开 JNI / ObjC++ 复杂度Expo Modules 或 Nitro
