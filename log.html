六层日志架构

一个生产级日志系统不是"一个 logger 打天下"，而是由 6 个关注点不同的层次组成，每层解决独立的问题：

层次关注点工具/方案输出目标
L1 应用日志 业务逻辑、调试信息 Pino / Winston（结构化 JSON） 文件 → 日志平台
L2 访问日志 HTTP 请求/响应、耗时 pino-http / 自定义 Interceptor 文件 → 日志平台
L3 异常追踪 未捕获异常、错误聚合 Sentry / Bugsnag Sentry Dashboard
L4 链路追踪 请求关联、跨服务追踪 Correlation ID / OpenTelemetry Jaeger / Zipkin
L5 指标采集 QPS、延迟、错误率 Prometheus / Datadog Grafana Dashboard
L6 操作审计 用户行为、数据变更 数据库表 + 异步写入 MySQL / 审计库

description L1 — 应用日志（结构化日志框架）

为什么选 Pino？

2024-2026 年 NestJS 社区共识：Pino 是生产环境首选。核心优势：

  • 性能碾压：基准测试中吞吐量是 Winston 的 5-10 倍，因为 JSON 序列化在 C++ 层完成
  • JSON 原生：输出即结构化 JSON，零配置
  • 生态整合：pino-http 自动记录 HTTP 请求日志，pino-pretty 开发环境美化输出
  • 传输分离：日志格式与日志去向解耦，通过 transport 管道输出到文件/stdout/远程

nestjs-pino 基础配置

// app.module.ts
import { LoggerModule } from 'nestjs-pino';

@Module({
  imports: [
    LoggerModule.forRoot({
      pinoHttp: {
        // 生产环境：纯 JSON
        // 开发环境：pino-pretty 美化
        transport:
          process.env.NODE_ENV !== 'production'
            ? { target: 'pino-pretty' }
            : undefined,
        // 自定义请求属性
        customProps: (req, res) => ({
          appName: 'fcm-push-server',
        }),
        // 自定义成功日志级别
        customLogLevel: (req, res, err) => {
          if (res.statusCode >= 500) return 'error';
          if (res.statusCode >= 400) return 'warn';
          return 'info';
        },
      },
    }),
  ],
})
export class AppModule {}

替换 NestJS 内置 Logger

// main.ts
import { NestFactory } from '@nestjs/core';
import { Logger } from 'nestjs-pino';

async function bootstrap() {
  const app = await NestFactory.create(
    AppModule,
    { bufferLogs: true }  // 防止初始化阶段日志丢失
  );

  // 用 Pino 替换 NestJS 内置 Logger
  app.useLogger(app.get(Logger));

  await app.listen(3000);
}
bootstrap();

Winston 备选方案（适合需要多 transport 的场景）

// winston-config.ts
import { WinstonModule } from 'nest-winston';
import * as winston from 'winston';

WinstonModule.forRoot({
  transports: [
    // 控制台：开发环境用 colorize，生产用 JSON
    new winston.transports.Console({
      format:
        process.env.NODE_ENV === 'production'
          ? winston.format.combine(
              winston.format.timestamp(),
              winston.format.json()
            )
          : winston.format.combine(
              winston.format.colorize(),
              winston.format.timestamp({ format: 'HH:mm:ss' }),
              winston.format.printf(({ timestamp, level, message, context }) =>
                `[${timestamp}] ${level} [${context || ''}] ${message}`
              ),
            ),
    }),
    // 文件：按大小轮转
    new winston.transports.File({
      filename: 'logs/error.log',
      level: 'error',
      maxsize: 50 * 1024 * 1024, // 50MB
      maxFiles: 14,
    }),
  ],
});
http L2 — 访问日志（HTTP 请求/响应）

pino-http（推荐方案）

nestjs-pino 内置 pino-http 中间件，自动为每个请求生成一行结构化日志，包含：

  • req — method、url、headers、remoteAddress
  • res — statusCode、headers
  • responseTime — 精确到毫秒
  • reqId — 自动生成的请求 ID（可自定义）
vs 自定义 Interceptor：pino-http 在 TCP 层捕获响应结束事件，比 RxJS tap 拦截器更准确（不会遗漏异常路径），且性能开销更低。

自定义请求日志字段

LoggerModule.forRoot({
  pinoHttp: {
    // 自定义请求序列化（脱敏 + 业务字段）
    customAttributeKeys: {
      req: 'request',
      res: 'response',
      err: 'error',
      reqId: 'requestId',
      responseTime: 'duration',
    },
    // 添加业务上下文
    customProps: (req, res) => ({
      userId: req.user?.id,
      appId: req.headers?.['x-app-id'],
      env: process.env.ENV_MODE,
    }),
    // 脱敏：不记录 Authorization 头
    redact: ['req.headers.authorization', 'req.body.password'],
  },
});
bug_report L3 — 异常追踪（错误捕获与上报）

全局异常过滤器（基础防线）

每个 NestJS 项目都应有全局异常过滤器，但它的职责仅是格式化响应和本地记录。真正的问题聚合和告警应交给 Sentry。

// all-exceptions.filter.ts
import { Catch, ArgumentsHost, HttpException, HttpStatus } from '@nestjs/common';
import { BaseExceptionFilter } from '@nestjs/core';
import { Logger } from 'nestjs-pino';

@Catch()
export class AllExceptionsFilter extends BaseExceptionFilter {
  private readonly logger = new Logger('ExceptionFilter');

  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const request = ctx.getRequest();
    const response = ctx.getResponse();

    const status = exception instanceof HttpException
      ? exception.getStatus()
      : HttpStatus.INTERNAL_SERVER_ERROR;

    // 结构化错误日志
    this.logger.error({
      message: exception instanceof Error ? exception.message : 'Unknown error',
      statusCode: status,
      method: request.method,
      url: request.url,
      requestId: request.id,  // pino-http 自动注入
      stack: exception instanceof Error ? exception.stack : undefined,
    });

    // 让 Sentry 捕获（见下文）
    // Sentry.captureException(exception);

    super.catch(exception, host);
  }
}

为什么需要 Correlation ID？

没有 Correlation ID，当一个请求经过 Controller → Service → 外部 API → 数据库，产生 10 条日志时，你无法将它们关联起来。尤其在并发场景下，日志交错排列，排查问题如同大海捞针。

方案一：nestjs-pino 内置 reqId（推荐，最简）

LoggerModule.forRoot({
  pinoHttp: {
    // 使用请求头中的 x-request-id，没有则自动生成
    genReqId: (req) =>
      req.headers['x-request-id'] || randomUUID(),
    // 响应头中返回 request-id
    customAttributeKeys: {
      reqId: 'requestId',
    },
  },
});
// 效果：每条日志自动附带 {"requestId":"abc-123"}

方案二：nestjs-cls（跨函数传递上下文）

当需要在日志之外的场景（如审计、多租户）传递请求上下文时，使用 nestjs-cls 封装 AsyncLocalStorage：

// app.module.ts
import { ClsModule } from 'nestjs-cls';

@Module({
  imports: [
    ClsModule.forRoot({
      global: true,
      middleware: {
        // 每个请求自动创建 CLS 上下文
        mount: true,
        setup: (cls, req) => {
          cls.set('requestId', req.headers['x-request-id'] || randomUUID());
          cls.set('userId', req.user?.id);
        },
      },
    }),
  ],
})
export class AppModule {}

// 任意 Service 中使用
import { ClsService } from 'nestjs-cls';

@Injectable()
export class MessageTaskService {
  constructor(private readonly cls: ClsService) {}

  sendPush() {
    const requestId = this.cls.get('requestId');
    // 可直接传给下游 API，无需手动透传参数
  }
}

analytics L5 — 指标采集（Metrics / APM）

为什么日志不够？

日志告诉你"发生了什么"，但无法回答：

  • 当前 QPS 是多少？比昨天高还是低？
  • P99 延迟是否超过 SLA？
  • 错误率突增时，是哪些接口出了问题？
  • FCM 推送成功率趋势如何？

这些需要指标（Metrics）来回答。

Prometheus + Grafana（推荐）

NestJS 审计日志实现模式

// 使用装饰器 + 拦截器模式（当前项目已采用此模式）

// 1. 自定义装饰器标记需要审计的操作
export const AuditAction = (action: string) =>
  SetMetadata('audit:action', action);

// 2. 拦截器在操作成功后异步写入审计记录
@Injectable()
export class AuditInterceptor implements NestInterceptor {
  intercept(context: ExecutionContext, next: CallHandler) {
    const action = this.reflector.get('audit:action', context.getHandler());

    return next.handle().pipe(
      tap((data) => {
        if (action) {
          // 异步写入，不阻塞响应
          this.auditService.log({
            userId: context.switchToHttp().getRequest().user.id,
            action,
            resource: context.getClass().name,
            timestamp: new Date(),
          }).catch(err =>
            this.logger.warn(`Audit log failed: ${err.message}`)
          );
        }
      }),
    );
  }
}

// 3. Controller 中使用
@Post()
@AuditAction('create-push-task')
createTask(@Body() dto: CreateTaskDto) { ... }

推荐传输架构（容器化部署）

┌──────────────────────┐
│   NestJS App (Pino)  │
│   输出 JSON 到 stdout │
└──────────┬───────────┘
           │
           ├──── stdout (JSON) ──▶ Fluentd / Promtail ──▶ Loki / ES
           │
           └──── Sentry SDK  ────────────────────────▶ Sentry

12-Factor App 原则：应用只管输出日志到 stdout，不负责日志的路由和存储。
最佳实践：容器化环境中，应用只管将 JSON 日志输出到 stdout/stderr，由 Kubernetes 的日志驱动（Fluentd/Promtail/Filebeat）负责收集和转发。这样应用不依赖日志存储后端，解耦更彻底。

compare Pino vs Winston 对比选型
维度 Pino Winston
性能 极快 — JSON 序列化在 C++ 层（sonic-boom） 中等 — 纯 JS JSON.stringify
Bundle 大小 ~30KB（核心） ~120KB（含依赖）
输出格式 JSON 原生，pino-pretty 开发美化 灵活 format chain（JSON / printf / 自定义）
Transport 独立进程（不阻塞主线程） 同进程（高并发时可能阻塞）
NestJS 集成 nestjs-pino — 官方推荐 nest-winston — 社区维护
HTTP 日志 pino-http 内置，零配置 需自定义 Interceptor 或 morgan
生态 pino-http / pino-pretty / pino-roll winston-daily-rotate / winston-elasticsearch
适用场景 高并发生产环境、微服务 需要复杂 format、多 transport 路由
结论：新项目首选 Pino。如果已有 Winston 基础设施且运行良好，无需强行迁移。

安装与初始化

# 安装
yarn add @sentry/nestjs @sentry/profiling-node

# main.ts — 尽早初始化
import * as Sentry from '@sentry/nestjs';

Sentry.init({
  dsn: process.env.SENTRY_DSN,
  environment: process.env.ENV_MODE,
  release: process.env.APP_VERSION,
  tracesSampleRate: 0.2,  // 20% 性能追踪采样
  profilesSampleRate: 0.1,
  integrations: [
    Sentry.nestIntegration(),
    Sentry.httpIntegration({ tracing: true }),
  ],
  // 过滤不需要上报的错误
  beforeSend(event, hint) {
    if (hint.originalException instanceof HttpException) {
      if (hint.originalException.getStatus() < 500) return null;
    }
    return event;
  },
});

全局 Sentry 过滤器

// sentry-exception.filter.ts
import { Catch, ArgumentsHost } from '@nestjs/common';
import { BaseExceptionFilter } from '@nestjs/core';
import * as Sentry from '@sentry/nestjs';

@Catch()
export class SentryExceptionFilter extends BaseExceptionFilter {
  catch(exception: unknown, host: ArgumentsHost) {
    Sentry.captureException(exception, {
      // 附加上下文
      contexts: {
        request: {
          method: host.switchToHttp().getRequest().method,
          url: host.switchToHttp().getRequest().url,
        },
      },
    });
    super.catch(exception, host);
  }
}

// main.ts 全局注册
app.useGlobalFilters(new SentryExceptionFilter());

手动上报（业务层错误）

// 对于需要额外上下文的业务错误
import * as Sentry from '@sentry/nestjs';

try {
  await this.fcmService.send(payload);
} catch (err) {
  Sentry.withScope((scope) => {
    scope.setTag('module', 'push-task');
    scope.setLevel('error');
    scope.setContext('pushPayload', {
      taskId: payload.taskId,
      appId: payload.appId,
      targetCount: payload.targets?.length,
    });
    Sentry.captureException(err);
  });
  throw err;
}

最小改动方案：在现有 log4js 基础上添加 requestId

如果暂时不做框架迁移，可以在现有架构上用最小改动获得 80% 的收益：

// common/middleware/correlation-id.middleware.ts
import { Injectable, NestMiddleware } from '@nestjs/common';
import { randomUUID } from 'crypto';

@Injectable()
export class CorrelationIdMiddleware implements NestMiddleware {
  use(req: any, res: any, next: () => void) {
    const requestId = req.headers['x-request-id'] || randomUUID();
    req.requestId = requestId;
    res.setHeader('x-request-id', requestId);
    next();
  }
}

// app.module.ts — 在 ConsumerModule 中注册
export class AppModule implements OnModuleInit {
  configure(consumer: MiddlewareConsumer) {
    consumer
      .apply(CorrelationIdMiddleware)
      .forRoutes('*');
  }
}

// common/log4js.ts — 修改日志函数，自动读取 requestId
export function accessLog(data: AccessLogDataType) {
  accessLogger.info({
    ...data,
    requestId: data.requestId || '-',
  });
}
