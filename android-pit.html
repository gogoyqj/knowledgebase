刘海屏 / 挖孔屏安全区 共性

expand_more
┌──────────────────────┐ │░░░░░░░░░░░░░░░░░░░░░│ ← 状态栏 (insets.top) │░░░┌──┐░░░░░░░░░░░░░░│ ← 刘海 / 挖孔 │░░░│ │░░░░░░░░░░░░░░│ │░░░└──┘░░░░░░░░░░░░░░│ │ │ │ 安全显示区域 │ │ │ │ │ │░░░░░░░░░░░░░░░░░░░░░│ ← 导航栏 / 手势条 │░░░░░░░░░░░░░░░░░░░░░│ (insets.bottom) └──────────────────────┘

原生 (Kotlin)

// Android 9+ 声明刘海支持
if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.P) {
    window.attributes.layoutInDisplayCutoutMode =
        WindowManager.LayoutParams
            .LAYOUT_IN_DISPLAY_CUTOUT_MODE_SHORT_EDGES
}

// 获取安全区 insets
ViewCompat.setOnApplyWindowInsetsListener(view) { v, insets ->
    val bars = insets.getInsets(
        WindowInsetsCompat.Type.systemBars()
    )
    v.setPadding(bars.left, bars.top,
                 bars.right, bars.bottom)
    insets
}

React Native

// ⚠️ SafeAreaView 在 Android 上不生效！
// 必须用 react-native-safe-area-context
import { useSafeAreaInsets }
  from 'react-native-safe-area-context';

function Screen() {
  const insets = useSafeAreaInsets();
  return (
    <View style={{
      paddingTop: insets.top,
      paddingBottom: insets.bottom
    }}>
      {/* 内容 */}
    </View>
  );
}
  • 各厂商刘海形状不同（水滴/挖孔/药丸），不能 hardcode 尺寸
  • 横屏时刘海会切到内容
  • LAYOUT_IN_DISPLAY_CUTOUT_MODE_DEFAULT 在全屏下自动加黑边
  • RN 的 SafeAreaView 仅 iOS 有效，Android 必须用第三方库
  • 某些 Android 机型 insets 返回 0，需要 fallback

软键盘（输入法）共性

expand_more
┌──────────────────────┐ │ │ │ App 内容 │ │ │ │ ┌──────────────────┐│ │ │ TextInput ││ ← 需要上推 │ └──────────────────┘│ │▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓│ ← 软键盘弹出 │▓▓▓ 搜狗 / Gboard ▓▓▓│ 高度不固定 │▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓│ └──────────────────────┘

原生 (Kotlin)

// 监听键盘高度
ViewCompat.setOnApplyWindowInsetsListener(view) { v, insets ->
    val imeVisible = insets.isVisible(
        WindowInsetsCompat.Type.ime()
    )
    val imeHeight = insets.getInsets(
        WindowInsetsCompat.Type.ime()
    ).bottom
    // 调整布局
    insets
}

React Native

// AndroidManifest.xml
<activity
  android:windowSoftInputMode="adjustResize"
/>

// JS 侧
<KeyboardAvoidingView
  behavior={
    Platform.OS === 'ios' ? 'padding' : 'height'
  }
  style={{ flex: 1 }}
>
  <TextInput />
</KeyboardAvoidingView>
  • adjustResize vs adjustPan 行为不一致
  • WindowInsetsCompat.Type.ime() Android 11+ 才可靠
  • 某些输入法（搜狗/百度）高度不标准，会弹跳
  • RN 的 KeyboardAvoidingView Android 用 height，用 padding 会跳
  • 全屏模式下键盘弹出不 resize，内容被完全遮挡

权限管理 共性

expand_more
Android 版本权限变化
10 (API 29)分区存储 (Scoped Storage)，READ_EXTERNAL_STORAGE 行为变化
11 (API 30)自动重置未使用 App 的权限
12 (API 31)精确闹钟 SCHEDULE_EXACT_ALARM，蓝牙权限细分
13 (API 33)通知权限 POST_NOTIFICATIONS，媒体权限细分
14 (API 34)前台服务类型声明，隐式 Intent 限制
15 (API 35)强制 edge-to-edge，部分权限行为再次调整

React Native 额外注意

// Android 13+ 通知权限
import { PermissionsAndroid } from 'react-native';

if (Platform.Version >= 33) {
  const result = await PermissionsAndroid.request(
    'android.permission.POST_NOTIFICATIONS'
  );
}
  • RN 的 PermissionsAndroid API 很基础，复杂权限链要自己编排
  • 某些 ROM request 返回 granted 但实际没授权
  • 权限被永久拒绝后 RN 无好的引导方案，需手动跳设置页
  • 后台定位需先有前台定位，不能直接请求

状态栏 & 导航栏 共性

expand_more
┌──────────────────────┐ │▓▓▓▓ 状态栏 ▓▓▓▓▓▓▓▓▓│ ← 沉浸式 / 透明 ├──────────────────────┤ 深色/浅色图标 │ │ │ App 内容 │ │ │ ├──────────────────────┤ │▓▓ 导航栏 / 手势条 ▓▓▓│ ← 三键 vs 手势 └──────────────────────┘ 高度不同

原生 (Kotlin)

// 沉浸式 (Android 11+)
WindowCompat.setDecorFitsSystemWindows(window, false)

// 传统方式 (Android 5-10)
window.statusBarColor = Color.TRANSPARENT
window.navigationBarColor = Color.TRANSPARENT

React Native

// 状态栏 (全局组件，页面间会互相影响!)
<StatusBar
  translucent
  backgroundColor="transparent"
  barStyle="light-content"
/>

// 导航栏颜色需要原生模块
import SystemNavigationBar
  from 'react-native-system-navigation-bar';
SystemNavigationBar.setNavigationColor('#000');
  • Android 5-11 每个版本沉浸式 API 都不同，兼容代码很长
  • 手势模式 vs 三键模式，底部安全区高度不同
  • Android 15 默认强制 edge-to-edge，老应用可能出问题
  • RN 的 StatusBar 是全局的，页面 A 设了会影响页面 B
  • RN 的 translucent 在某些机型上内容会跑到状态栏下面

后台任务 & 推送 共性

expand_more
warning
国内无法使用 FCM，需要接入厂商推送通道（小米/华为/OPPO/vivo）

原生 (Kotlin)

// Android 8+ 后台 Service 限制
// 需要改用 WorkManager 或 Foreground Service
val workRequest = OneTimeWorkRequestBuilder<MyWorker>()
    .setConstraints(Constraints.Builder()
        .setRequiredNetworkType(NetworkType.CONNECTED)
        .build())
    .build()
WorkManager.getInstance(context).enqueue(workRequest)

React Native

// Headless JS (Android 后台任务)
// 在很多厂商 ROM 上会被杀
import messaging
  from '@react-native-firebase/messaging';

const token = await messaging().getToken();
  • Android 8+ 后台 Service 限制，AlarmManager 在 Doze 模式不触发
  • Android 12+ 不能从后台启动前台服务
  • 各厂商 ROM 额外的后台杀死逻辑（MIUI/ColorOS/HarmonyOS）
  • RN 的 Headless JS 在很多机型上被杀
  • 推送需要厂商通道聚合，推荐用推送 SDK 聚合方案

autorenew

生命周期 & 状态恢复

expand_more
Activity 生命周期 (配置变更会重建!) onCreate ──→ onStart ──→ onResume ↑ │ │ onDestroy │ onPause │ ↑ ↓ └── onRestart ←── onStop │ 配置变更 (横竖屏/语言/ │ 深色模式) ─────────────┘ → onSaveInstanceState → onDestroy → onCreate(savedInstanceState)
// Bundle 有大小限制 (~1MB)
// 超了会 TransactionTooLargeException
override fun onSaveInstanceState(outState: Bundle) {
    super.onSaveInstanceState(outState)
    // 只保存轻量数据!
    outState.putString("key", value)
}
  • 横竖屏切换、语言切换、深色模式切换都会导致 Activity 重建
  • savedInstanceState Bundle 有 ~1MB 限制
  • onSaveInstanceState 在 API 28+ 于 onStop 之后调用
  • 系统低内存杀进程后恢复，全局变量全部丢失
  • 多窗口模式下 onResume 不代表 App 可见

图片加载

expand_more 
// 正确的两步加载：先获取尺寸，再降采样
val options = BitmapFactory.Options().apply {
    inJustDecodeBounds = true  // 只读尺寸
}
BitmapFactory.decodeStream(inputStream, null, options)

options.inSampleSize = calculateInSampleSize(
    options, reqWidth, reqHeight
)
options.inJustDecodeBounds = false
val bitmap = BitmapFactory.decodeStream(
    inputStream2, null, options
)
  • 大图不降采样直接加载会 OOM
  • BitmapFactory.decodeStream 只能读一次，需要先获取尺寸再解码
  • HEIC/HEIF 格式在低版本不支持
  • Content URI 获取真实路径是经典难题，没有通用方案
  • 推荐直接用 Glide/Coil，不要手写 Bitmap 加载

warning

Jetpack Compose 专属坑

expand_more
  • 重组（Recomposition）范围过大导致性能问题，需用 derivedStateOf 控制
  • LaunchedEffect key 变化会取消并重启，容易遗漏
  • remember 在配置变更后丢失，需用 rememberSaveable
  • 与 View 系统互操作（AndroidView）时生命周期管理复杂
  • Lazy 列表嵌套滚动冲突
extension

原生模块 & 新架构

expand_more
旧架构 (Bridge) 新架构 (JSI / TurboModules) JS ──JSON──→ Bridge ──→ Native JS ──直接调用──→ Native ↑ ↓ ↑ └──JSON────────┘ 直接返回 (序列化瓶颈, 60fps 上限) (零拷贝, 高性能)
// 旧架构 (Bridge)
import { NativeModules } from 'react-native';
const { MyModule } = NativeModules;

// 新架构 (Turbo Modules / JSI)
import MyModule from './NativeMyModule';
  • 新架构（Fabric / TurboModules）兼容性问题多，很多第三方库未适配
  • Bridge JSON 序列化大数据会卡顿
  • 原生模块线程模型复杂：UI 操作必须在主线程
  • NativeModules 返回 null 通常是链接问题
  • iOS/Android 原生模块接口需分别实现

导航 (React Navigation)

expand_more

Gradle & 构建配置

expand_more
版本兼容矩阵 (四个必须匹配!) ┌─────────────┬───────────────┬──────────────┐ │ RN 版本 │ Gradle 版本 │ AGP 版本 │ ├─────────────┼───────────────┼──────────────┤ │ 0.73 │ 8.4 │ 8.1.x │ │ 0.74 │ 8.6 │ 8.2.x │ │ 0.75+ │ 8.8+ │ 8.5.x │ └─────────────┴───────────────┴──────────────┘ JDK 版本也要对齐 (推荐 JDK 17)
  • Gradle / AGP / JDK / RN 四者版本必须匹配，错一个编译失败

  • 某些原生库只有 armeabi-v7a，缺少 arm64-v8a
  • android/build.gradle 的 repositories 配置容易遗漏
