为什么选择 Prisma？

Prisma 是一个下一代 Node.js / TypeScript ORM，专注于简化数据库操作、提供类型安全、以及自动化数据库迁移。它由三部分组成：

data_object Prisma Schema

声明式 Schema 语言，定义数据模型、关系和数据库连接。一份 schema.prisma 是单一事实来源。

terminal Prisma Migrate

自动对比 Schema 变更，生成 SQL Migration 文件。版本化管理数据库结构演进。

code Prisma Client

自动生成的、完全类型安全的数据库客户端。告别手写 SQL 拼接和类型断言。

explore Prisma Studio

可视化数据库浏览和编辑工具。无需离开浏览器即可查看和修改数据。

Prisma vs 其他 ORM

与传统 ORM 相比，Prisma 在多个维度上有显著差异：

维度 Prisma TypeORM / Sequelize
类型安全 自动生成 编译时检查 手动定义接口，易遗漏
Schema 定义 专用 .prisma DSL，简洁直观 装饰器 / 类定义，较冗长
Migration 自动生成 SQL diff 手写 Migration 或有限自动生成
查询构建 链式 API + 自动补全 QueryBuilder / Raw SQL
关系查询 嵌套读写 一步到位 需手动 join 或多次查询
数据库支持 PostgreSQL, MySQL, SQLite, SQL Server, MongoDB, CockroachDB 类似，但适配层质量参差

核心优势详解

verified 端到端类型安全

从 Schema 到查询结果，TypeScript 类型全程贯穿。修改 Schema 后重新生成 Client，编译器会指出所有需要更新的代码。

swap_horiz 自动 Migration

修改 Schema → 运行 prisma migrate dev → 自动生成 SQL 脚本。无需手写 DDL，支持多人协作和冲突检测。

account_tree 直观的关系建模

用 @relation 声明一对一、一对多、多对多，Prisma 自动处理外键和中间表。嵌套创建/查询一步到位。

query_stats 智能查询优化

Prisma Client 自动将嵌套查询优化为少量 SQL 语句，避免 N+1 问题。include 和 select 精确控制返回字段。

grass Prisma Seed & 模拟数据

内置 prisma db seed 命令，配合 模拟数据工厂 轻松填充开发/测试数据库。

integration_instructions 与 PostgreSQL 深度集成

原生支持 PostgreSQL 特有类型：Enum、Json/JsonB、Array、UUID、全文搜索等。

check_circle
一句话总结：Prisma 让你用写 TypeScript 的方式操作数据库 —— 类型安全、自动补全、自动迁移，大幅减少样板代码和人为错误。

Migration 工作流总览

Prisma Migrate 是 Prisma 的数据库 Schema 迁移工具。它的核心能力是：对比你修改后的 schema.prisma 与当前数据库状态，自动生成对应的 SQL 变更脚本。

┌─────────────────────────────────────────────────────────┐ │ Prisma Migration 工作流程 │ ├─────────────────────────────────────────────────────────┤ │ │ │ ① 开发者修改 schema.prisma │ │ 例: 新增字段、添加模型、修改关系 │ │ │ │ │ ▼ │ │ ② 运行 prisma migrate dev --name xxx │ │ │ │ │ ▼ │ │ ③ Prisma 引擎自动计算 diff │ │ ├─ 对比 schema.prisma (期望状态) │ │ └─ 对比数据库当前状态 (通过 shadow DB) │ │ │ │ │ ▼ │ │ ④ 生成 SQL Migration 文件 │ │ prisma/migrations/20240831_xxx/migration.sql │ │ (纯 SQL, 可人工审查/修改) │ │ │ │ │ ▼ │ │ ⑤ 执行 Migration → 更新数据库 │ │ │ │ │ ▼ │ │ ⑥ 重新生成 Prisma Client (自动) │ │ → 类型定义立刻反映新 Schema │ │ │ └─────────────────────────────────────────────────────────┘
terminal

核心命令详解

开发阶段：prisma migrate dev

在本地开发时使用。执行以下步骤：

  1. 检测 schema.prisma 的变更
  2. 在 shadow database（临时数据库）上模拟执行，验证 SQL 正确性
  3. 生成 Migration SQL 文件到 prisma/migrations/
  4. 将 Migration 应用到开发数据库
  5. 自动运行 prisma generate 更新 Client
# 基本用法
npx prisma migrate dev --name add_user_avatar

# 输出示例：
# Prisma schema loaded from prisma/schema.prisma
# The following migration(s) have been created and applied from new schema changes:
#
# prisma/migrations/20240831120000_add_user_avatar/
#   └── migration.sql
#
# Your database is now in sync with your schema.
lightbulb
Shadow Database 是什么？
Prisma 会自动创建一个临时数据库，把所有历史 Migration + 当前变更重新执行一遍，来验证生成的 SQL 是否正确。验证通过后才应用到你的开发数据库。PostgreSQL 的 shadow DB 由 Prisma 自动管理，无需手动配置。

生产部署：prisma migrate deploy

在 CI/CD 或生产环境使用。不会生成新 Migration，只执行已有的待迁移文件：

# 生产部署脚本
npx prisma migrate deploy
npx prisma generate
node dist/server.js

# 输出示例：
# 2 migrations found in prisma/migrations
# 1 migration already applied
# Applying migration `20240831120000_add_user_avatar`
# Done in 230ms
warning
重要区别：migrate dev = 生成 + 执行（开发用），migrate deploy = 仅执行（生产用）。生产环境绝不使用 migrate dev，因为它需要 shadow database 并可能重置数据。

其他实用命令

# 查看 Migration 状态
npx prisma migrate status

# 重置数据库 (开发环境! 会清空数据)
npx prisma migrate reset

# 从已有数据库生成初始 Migration (遗留项目)
npx prisma migrate diff --from-empty --to-schema-datamodel prisma/schema.prisma --script > init.sql
description

自动生成的 Migration 文件

每次运行 migrate dev，Prisma 会在 prisma/migrations/ 下创建带时间戳的目录，里面是纯 SQL 文件：

prisma/
├── schema.prisma
└── migrations/
    ├── 20240801100000_init/
    │   └── migration.sql
    ├── 20240815140000_add_posts/
    │   └── migration.sql
    └── 20240831120000_add_user_avatar/
        └── migration.sql

── migration_lock.toml   (锁定数据库供应商)

一个典型的自动生成的 Migration SQL 示例：

-- prisma/migrations/20240831120000_add_user_avatar/migration.sql

-- AlterTable: 给 User 表添加 avatar 字段
ALTER TABLE "User" ADD COLUMN "avatar" TEXT;

-- CreateIndex: 为 email 创建唯一索引
CREATE UNIQUE INDEX "User_email_key" ON "User"("email");
check_circle
关键点：生成的是纯 SQL 文件，你可以：
  • 人工审查 — 确认生成的 SQL 符合预期
  • 手动修改 — 添加自定义 SQL（如数据迁移、索引优化）
  • 版本控制 — 提交到 Git，团队共享 Migration 历史

Migration 的典型场景

场景 1：添加新字段

// schema.prisma — 新增 bio 字段
model User {
  id    Int     @id @default(autoincrement())
  email String  @unique
  name  String
  bio   String?  // 新增: 可选字段
  posts Post[]
}
-- 自动生成的 migration.sql
ALTER TABLE "User" ADD COLUMN "bio" TEXT;

场景 2：添加关系

// schema.prisma — User 和 Post 的一对多关系
model User {
  id    Int     @id @default(autoincrement())
  posts Post[]  // 一对多
}

model Post {
  id       Int     @id @default(autoincrement())
  title    String
  author   User   @relation(fields: [authorId], references: [id])
  authorId Int
}
-- 自动生成的 migration.sql
ALTER TABLE "Post" ADD COLUMN "authorId" INTEGER NOT NULL;
ALTER TABLE "Post" ADD CONSTRAINT "Post_authorId_fkey"
  FOREIGN KEY ("authorId") REFERENCES "User"("id") ON DELETE RESTRICT ON UPDATE CASCADE;

场景 3：数据迁移（自定义 SQL）

当 Migration 不仅涉及结构变更，还需要迁移现有数据时，可以在生成的 SQL 中手动添加：

-- 自动生成的结构变更
ALTER TABLE "User" ADD COLUMN "fullName" TEXT;

-- ↓ 手动添加: 将旧的 name 数据复制到 fullName
UPDATE "User" SET "fullName" = "name";

-- 然后再删除旧字段
ALTER TABLE "User" DROP COLUMN "name";
lightbulb
这就是你记忆中的"自动生成数据升级脚本"：Prisma 自动生成 DDL（结构变更），你可以在同一个 Migration 文件中补充 DML（数据变更），实现结构 + 数据的一体化迁移。

Prisma Schema 基础

Schema 是 Prisma 的单一事实来源，定义了数据模型、数据库连接和生成器：

// prisma/schema.prisma

// 1. 数据源配置 — 指向 PostgreSQL
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

// 2. 生成器 — 生成 Prisma Client
generator client {
  provider = "prisma-client-js"
}

// 3. 数据模型
model User {
  id        Int      @id @default(autoincrement())
  email     String   @unique
  name      String
  role      Role     @default(USER)
  posts     Post[]
  profile   Profile?
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@map("users")  // 映射到数据库表名
}

enum Role {
  USER
  ADMIN
  MODERATOR
}
info
PostgreSQL 特有支持：Prisma 原生支持 PostgreSQL 的 enum、Json、Bytes、Decimal、BigInt 等类型，以及 @db.Uuid、@db.Text 等数据库特定属性。

类型安全的查询

Prisma Client 根据 Schema 自动生成类型，所有查询都有完整的 TypeScript 支持：

import { PrismaClient } from '@prisma/client'
const prisma = new PrismaClient()

// ✅ 创建 — 自动补全字段名和类型
const user = await prisma.user.create({
  data: {
    email: 'alice@example.com',
    name: 'Alice',
    // 嵌套创建 — 一步创建 User + Profile
    profile: {
      create: { bio: 'Hello!' }
    }
  },
  // include: 返回时包含关联数据
  include: { profile: true }
})

// ✅ 查询 — 类型安全的过滤条件
const posts = await prisma.post.findMany({
  where: {
    author: { email: 'alice@example.com' },
    published: true,
  },
  include: {
    author: {
      select: { name: true, email: true }  // 精确选择字段
    }
  },
  orderBy: { createdAt: 'desc' },
  take: 10,  // 分页
})

// ✅ 更新 — 支持原子操作
const updated = await prisma.user.update({
  where: { id: 1 },
  data: {
    name: 'Alice Updated',
    role: ADMIN,
  }
})

// ✅ 事务 — 多个操作原子执行
const [user, post] = await prisma.$transaction([
  prisma.user.create({ data: { email: 'bob@test.com', name: 'Bob' } }),
  prisma.post.create({ data: { title: 'First Post', authorId: 1 } }),
])

高级查询能力

聚合与分组

// 聚合
const stats = await prisma.post.aggregate({
  where: { published: true },
  _count: true,
  _avg: { views: true },
  _max: { views: true },

// 分组
const grouped = await prisma.post.groupBy({
  by: ['authorId'],
  _count: true,
  having: {
    views: { _avg: { gt: 100 } }  // HAVING 子句
  }
})

原始 SQL (当 ORM 不够用时)

// 使用 $queryRaw 执行原始 SQL
const result = await prisma.$queryRaw`
  SELECT u.name, COUNT(p.id) as post_count
  FROM users u
  LEFT JOIN posts p ON p."authorId" = u.id
  GROUP BY u.name
  ORDER BY post_count DESC
  LIMIT 10
`

// 使用 $executeRaw 执行写操作
await prisma.$executeRaw`
  UPDATE users SET role = 'ADMIN' WHERE id = ${userId}
`

JSON 字段查询 (PostgreSQL JsonB)

// Schema
model Product {
  id   Int                  @id @default(autoincrement())
  name String
  meta Json                 // PostgreSQL 中存储为 jsonb
}

// 查询 JSON 内部字段
const products = await prisma.product.findMany({
  where: {
    meta: {
      path: ['color'],       // 访问 meta.color
      equals: 'red'
    }
  }
})

Prisma Client 单例（避免连接池耗尽）

// src/lib/prisma.ts
import { PrismaClient } from '@prisma/client'

const globalForPrisma = globalThis as unknown as {
  prisma: PrismaClient | undefined
}

export const prisma =
  globalForPrisma.prisma ??
  new PrismaClient({
    log: process.env.NODE_ENV === 'development'
      ? ['query', 'error', 'warn']
      : ['error'],
  })

if (process.env.NODE_ENV !== 'production') {
  globalForPrisma.prisma = prisma
}
engineering

Migration 最佳实践

check 始终审查生成的 SQL

自动生成的 SQL 通常是正确的，但复杂变更（如列类型转换、大规模数据迁移）需要人工审查。

check Migration 命名要语义化

--name add_user_avatar 而非 --name update。清晰的命名让 Git history 一目了然。

check 不要修改已部署的 Migration

已推送到生产的 Migration 文件不要修改。需要新变更就创建新 Migration。

check 使用 migrate deploy 部署

生产环境只用 migrate deploy，它安全地按顺序执行待迁移文件。

CI/CD 中的 Migration 流程

# Dockerfile 或 CI 脚本

# 1. 安装依赖
npm ci

# 2. 生成 Prisma Client
npx prisma generate

# 3. 执行 Migration (只运行待执行的)
npx prisma migrate deploy

# 4. 启动应用
node dist/server.js
tips_and_updates

性能优化技巧

speed 使用 select 精确查询

只查需要的字段，减少网络传输和内存占用。比 include 更高效。

batch_prediction 批量操作

用 createMany、updateMany、deleteMany 替代循环单条操作。

database 连接池配置

PostgreSQL 连接字符串添加 ?connection_limit=10 控制连接数。

analytics 查询日志分析

开发环境开启 log: ['query']，观察生成的 SQL，发现 N+1 问题。

// ❌ N+1 问题
const users = await prisma.user.findMany()
for (const user of users) {
  const posts = await prisma.post.findMany({
    where: { authorId: user.id }  // 每个用户一次查询!
  })
}

// ✅ 使用 include 一次查完
const users = await prisma.user.findMany({
  include: { posts: true }  // 一条 SQL 搞定
})

与 Next.js 集成

Prisma 与 Next.js 的 Server Components / Server Actions 天然契合：

// app/posts/page.tsx — Server Component 中直接查询
import { prisma } from '@/lib/prisma'

export default async function PostsPage() {
  const posts = await prisma.post.findMany({
    include: { author: { select: { name: true } } },
    orderBy: { createdAt: 'desc' },
  })

  return (
    <div>
      {posts.map(post => (
        <article key={post.id}>
          <h2>{post.title}</h2>
          <p>by {post.author.name}</p>
        </article>
      ))}
    </div>
  )
}

// app/actions.ts — Server Action 中操作数据库
'use server'
import { prisma } from '@/lib/prisma'
import { revalidatePath } from 'next/cache'

export async function createPost(formData: FormData) {
  await prisma.post.create({
    data: {
      title: formData.get('title') as string,
      authorId: 1,
    }
  })
  revalidatePath('/posts')
}
check_circle
最佳搭配：Next.js Server Components 可以直接 await Prisma 查询，无需 API 层。Server Actions 处理写操作。整个数据层零客户端 JS。
