account_tree 核心架构与进程模型

本质：Chromium + Node.js 的 C++ 层融合

Electron 不是两个独立运行时拼在一起，而是在 同一个 V8 Isolate 中同时注入 Chromium 的 Web API 和 Node.js 的系统 API，通过 Context 隔离访问权限。

│                      一个 V8 Isolate                        │
│                                                             │
│  ┌─────────────────────┐   ┌─────────────────────┐       │
│  │ Context A (preload) │   │ Context B (页面)    │       │
│  │                     │   │                     │       │
│  │ Chromium Web API ✓  │   │ Chromium Web API ✓  │       │
│  │ Node.js API ✓       │   │ Node.js API ✗       │       │
│  │ require ✓           │   │ require ✗           │       │

memory V8 Isolate 与 Context 隔离

概念层级

概念含义
V8 Isolate一个引擎实例 = 一个线程 + 一个堆 + 一个 GC
V8 Context一个执行上下文 = 独立的 globalThis + 内置对象

一个 Isolate 可以有多个 Context，它们共享同一个堆，但各自有不同的全局对象。

隔离机制

不是线程隔离，不是进程隔离，是 V8 Context 隔离。

本质：同一个 V8 Isolate 中创建两个 Context，每个 Context 有自己的 globalThis，互相看不到对方的全局变量。

底层调用 v8::Context::New(isolate)（C++ API），不是 Node.js 的 vm.createContext()（那是 JS 层封装）。

contextIsolation 配置效果

关闭 不安全

// preload 和页面共享同一个 Context
// 页面可以直接: window.require('fs')
// 恶意网页可以读写任意文件

开启 默认安全

// preload 和页面在不同 Context 中
// 页面看不到 require / process
// 必须通过 contextBridge 暴露 API
只有一个 V8 实例：Chromium 和 Node.js 共享同一个 V8 Isolate。Node.js 不是独立的 JS 引擎，它是一组用 C++ 写的模块（fs, http, path...），通过 V8 的 binding 机制注册到同一个 V8 实例中。两者的事件循环（libuv + Chromium MessagePump）也合并为一个。
swap_horiz contextBridge 跨 Context 通信

contextBridge 是什么

一个 API 桥接工具，作用是让 preload 脚本把指定的函数/数据安全地暴露给页面 JS 使用。本质就是往页面的 window 上注入属性，但通过 C++ 层实现跨 Context 的属性注入。

// preload.js
const { contextBridge, ipcRenderer } = require('electron')

contextBridge.exposeInMainWorld('electronAPI', {
  getUser: (id) => ipcRenderer.invoke('get-user', id),
  saveFile: (data) => ipcRenderer.invoke('file:save', data),
  onUpdate: (cb) => ipcRenderer.on('update', (_, d) => cb(d)),
})

通信机制：结构化克隆 + Context 切换

不是序列化（JSON），不是 IPC，是 V8 层面的对象遍历 + 在目标 Context 中直接创建新对象。

页面调用 proxy.getUser(123)
→
参数克隆到 preload Context
→
执行真实函数
→
返回值克隆回页面 Context

数据传递规则

类型传递方式说明
number / string / boolean / null / undefined直接复制V8 内部 immutable，零开销
普通对象 / 数组递归克隆在目标 Context 创建新对象
Date / RegExp / Map / Set / TypedArray递归克隆重建实例
函数转为代理函数调用时穿越 Context 边界
Promise转为代理 Promise.then/.catch 桥接状态
Symbol / WeakMap / WeakRef / DOM 节点不可传递返回 undefined

循环引用处理

内部维护 visited 集合 + cache 映射（原始对象 → 克隆对象），遇到已访问的对象时返回已克隆的引用，而不是无限递归。

const a = { name: 'A' }
const b = { name: 'B' }
a.friend = b;  b.friend = a  // 循环引用

contextBridge.exposeInMainWorld('data', { a, b })

// 页面中
window.data.a.friend === window.data.b        // true ✓
window.data.a.friend.friend.friend.name       // 'B' 'A' 'B' ...
循环引用关系完整保留。核心：先创建空壳放入 cache，再递归填充属性，遇到已访问对象从 cache 取出已创建的克隆。

exposeInMainWorld 命名冲突

直接覆盖已有全局变量，没有警告。解决方案：用唯一命名空间。

// ✓ 推荐：单一命名空间，带项目前缀
contextBridge.exposeInMainWorld('myAppName', {
  window: { minimize, maximize, close },
  file: { open, save },
  onUpdate: (cb) => { ... }
})

// ✗ 避免：多个顶级 key、太通用的名字
contextBridge.exposeInMainWorld('api', { ... })      // 容易冲突
contextBridge.exposeInMainWorld('config', { ... })   // 容易冲突
call_merge 函数代理与 Promise 代理

函数代理

代理函数是一个全新的函数对象，和原始函数只在调用时有数据桥接，其他时候毫无关联。

能用的（管道模式）

// 无状态，只传数据
(id) => ipcRenderer.invoke('get-user', id)

// 带简单校验
(data) => {
  if (!data.path) throw new Error('invalid')
  return ipcRenderer.invoke('save', data)
}

不能用的（依赖自身状态）

// 依赖闭包 — 丢失
const count = 0
exposeInMainWorld('inc', () => count++)

// 依赖 this — 指向不对
exposeInMainWorld('obj', {
  value: 0,
  inc() { this.value++ }
})
代理函数丢失的特性：name、length、prototype、this 指向、闭包变量、Symbol 属性、WeakMap 关联、arguments.callee。本质就是一个只负责传数据的管道。

Promise 代理

preload 返回的 Promise 在页面 Context 中创建一个新的 Promise 壳，原始 Promise 的结果通过 .then/.catch 桥接过来。

页面调用 proxy.getUser(123)
→
preload 执行 ipcRenderer.invoke
→
返回 preload 的 Promise
→
创建页面 Promise 壳

原始 Promise 的 .then 注册回调，resolved 时把值克隆到页面 Context 并 resolve 页面的 Promise。整个 .then 链都在页面 Context 中执行，只有第一次返回值是跨 Context 的。

函数作为参数（回调）

页面传函数给 preload 时，contextBridge 在 preload Context 中创建代理，调用时切回页面 Context 执行原始函数。回调在页面 Context 中执行，能访问 DOM。

// preload.js
contextBridge.exposeInMainWorld('api', {
  onProgress: (callback) => {
    ipcRenderer.on('download:progress', (_, data) => {
      callback(data)  // data 克隆到页面 Context，callback 在页面执行
    })
  }
})

// 页面中 — callback 能操作 DOM
window.api.onProgress((data) => {
  document.getElementById('bar').style.width = data.percent + '%'
})
build C++ Bindings 机制

什么是 Bindings

把 C++ 函数注册到 V8 中，让 JS 能直接调用。不是代理（拦截转发），是绑定（注册 + 直接调用）。

// C++ 绑定函数
void ReadFileSync(const FunctionCallbackInfo<Value>& args) {
  String::Utf8Value path(isolate, args[0]);
  int fd = open(*path, O_RDONLY);    // POSIX 系统调用
  read(fd, buf, size);               // 读文件
  args.GetReturnValue().Set(Buffer::New(isolate, buf, size));
}

// 注册到 V8
NODE_SET_METHOD(target, "readFileSync", ReadFileSync)

JS 调用 fs.readFileSync() 时，V8 查表找到 C++ 函数地址，直接执行。

启动优化

  • 按需加载 — require() 放到函数内，启动时不加载
  • 延迟初始化 — 数据库连接等放到首次使用时
  • 隐藏窗口预创建 — show: false + ready-to-show 事件
  • 窗口池 — 复用窗口而不是每次创建销毁
  • 代码分割 — 路由级别 import()，只加载当前页面

渲染优化

  • 虚拟列表 — 只渲染可见区域（react-window）
  • 减少重渲染 — React.memo / useMemo / useCallback
  • 图片优化 — WebP + 懒加载 + 合适尺寸
  • Web Worker — 重计算移到 Worker，不阻塞 UI
  • 流式处理 — 大文件用 Stream，不一次性读入内存

内存优化

  • 事件监听器及时移除 — ipcRenderer.removeListener()
  • 定时器及时清理 — clearInterval()
  • 限制缓存大小 — LRU 缓存，避免只增不减
  • 主动 GC — global.gc()（需 --expose-gc）

IPC 优化

  • 批量调用 — 合并多次小 IPC 为一次
  • 减少数据量 — 只传必要字段，不传整个大对象
  • 流式传输 — 大数据用流，不一次性传完

electron-updater 全量更新

配合 electron-builder 使用，支持全量/差量更新，自动签名验证。

// main.js — 更新管理器
const { autoUpdater } = require('electron-updater')
const log = require('electron-log')

class UpdateManager {
  constructor(mainWindow) {
    this.mainWindow = mainWindow
    this.setup()
  }

  setup() {
    autoUpdater.logger = log
    autoUpdater.autoDownload = false       // 不自动下载，先询问用户
    autoUpdater.autoInstallOnAppQuit = true // 退出时自动安装

    // 发现新版本
    autoUpdater.on('update-available', async (info) => {
      const { response } = await dialog.showMessageBox({
        type: 'info',
        buttons: ['立即更新', '稍后'],
        title: '发现新版本',
        message: `版本 ${info.version} 已发布`
      })
      if (response === 0) autoUpdater.downloadUpdate()
    })

    // 下载进度
    autoUpdater.on('download-progress', (progress) => {
      this.mainWindow.setProgressBar(progress.percent / 100)
    })

    // 下载完成，提示重启
    autoUpdater.on('update-downloaded', () => {
      dialog.showMessageBox({
        type: 'info',
        buttons: ['重启', '稍后'],
        title: '更新就绪',
        message: '新版本已下载，重启后生效'
      }).then(() => autoUpdater.quitAndInstall())
    })

    autoUpdater.on('error', (err) => log.error('更新失败:', err))
  }

  checkForUpdates() { autoUpdater.checkForUpdates() }
}

热更新原理（Bundle Hot Update）

只更新渲染进程的前端资源（JS/CSS/HTML），不涉及主进程，用户无感知。

热更新实现

// main.js — 热更新管理器
const fs = require('fs')
const path = require('path')
const crypto = require('crypto')
const AdmZip = require('adm-zip')

class HotUpdater {
  constructor() {
    this.bundleDir = path.join(app.getPath('userData'), 'bundle')
    this.currentVersion = '1.0.0'
  }

  // 启动时检查更新
  async checkAndUpdate() {
    try {
      // 1. 获取远程版本信息
      const res = await fetch('https://your-server.com/api/version')
      const { version, downloadUrl, sha256 } = await res.json()

      // 2. 版本对比
      if (this.compareVersion(version, this.currentVersion) <= 0) return

      // 3. 下载增量包
      const zipPath = path.join(app.getPath('temp'), 'hot-update.zip')
      await this.download(downloadUrl, zipPath)

      // 4. 完整性校验
      const hash = this.sha256File(zipPath)
      if (hash !== sha256) throw new Error('SHA256 校验失败')

      // 5. 解压覆盖
      const zip = new AdmZip(zipPath)
      zip.extractAllTo(this.bundleDir, true)

      // 6. 更新版本号
      this.currentVersion = version

      // 7. 通知渲染进程刷新
      mainWindow.webContents.send('hot-reload')
    } catch (e) {
      log.error('热更新失败，使用内置版本:', e)
    }
  }

  // 加载入口：优先用热更新的 bundle
  getIndexPath() {
    const hotPath = path.join(this.bundleDir, 'index.html')
    if (fs.existsSync(hotPath)) return hotPath
    return path.join(__dirname, 'dist/index.html')  // 内置版本
  }

  sha256File(filePath) {
    const data = fs.readFileSync(filePath)
    return crypto.createHash('sha256').update(data).digest('hex')
  }
}

注意事项与限制

  • 回退机制 — 热更新失败时必须能回退到内置 Bundle，不能让应用挂掉
  • 完整性校验 — 下载的 ZIP 必须做 SHA256 校验，防止中间人篡改
  • 版本兼容 — 热更新的 Bundle 版本必须与当前主进程版本兼容，否则 IPC 会出错
  • macOS 签名 — 全量更新必须代码签名，否则 macOS Gatekeeper 会拦截
  • Windows Defender — 未签名的安装包可能被误报为病毒
  • 增量包大小 — 热更新 ZIP 应尽量小，只包含变更文件
  • 并发安全 — 多窗口场景下，热更新通知要广播到所有窗口
  • electron-log — 更新过程必须记录日志，方便排查问题

Context 隔离同一个 Isolate 中创建多个 Context，各自有不同的 globalThis，不是线程隔离也不是进程隔离
contextBridge跨 Context 的属性注入器，通过结构化克隆传递数据，函数转为代理函数，Promise 转为代理 Promise
