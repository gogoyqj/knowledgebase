1WebGPU 是什么

WebGPU 是由 W3C GPU for the Web 工作组制定的下一代 Web 图形与计算 API。它在设计上借鉴了 Vulkan、Metal 和 Direct3D 12 的低级抽象理念，为 JavaScript / WebAssembly 提供对 GPU 硬件的高效访问。

核心设计目标

  • 低开销 — 减少驱动层的状态验证和隐式同步，将控制权交给开发者
  • 跨平台统一 — 同一套 API 底层映射到 Vulkan (Android/Linux)、Metal (macOS/iOS)、D3D12 (Windows)
  • 计算着色器 (Compute Shader) — 一等公民，不再需要 hack 渲染管线来做 GPGPU
  • 安全沙箱 — 浏览器进程隔离 GPU 命令，防止越界访问和信息泄漏
💡

WebGPU 不是 WebGL 3.0。它是一套全新的 API 设计，与 WebGL（基于 OpenGL ES）没有直接升级关系。两者可以共存。

3初始化设备

WebGPU 的入口是 navigator.gpu。获取设备是一个异步过程：先请求 Adapter（物理/逻辑 GPU 抽象），再请求 Device（逻辑设备实例）。

完整初始化流程

// ① 检查浏览器支持
if (!navigator.gpu) {
  throw new Error('WebGPU 不受支持');
}

// ② 请求适配器 — 代表一个物理 GPU 或模拟层
const adapter = await navigator.gpu.requestAdapter({
  powerPreference: 'high-performance',  // 'low-power' | 'high-performance'
});
if (!adapter) throw new Error('没有可用的 GPU 适配器');

// ③ 查询适配器能力（可选，用于适配不同硬件）
console.log(adapter.features);   // 如 'texture-compression-bc', 'timestamp-query'
console.log(adapter.limits);     // 如 maxBufferSize, maxTextureDimension2D

// ④ 请求逻辑设备 — 所有 GPU 资源和命令都绑定到 Device
const device = await adapter.requestDevice({
  requiredFeatures: [],           // 需要启用的额外特性
  requiredLimits: {               // 请求超出默认值的限制
    maxBufferSize: 256 * 1024 * 1024,
  },
});

// ⑤ 错误监听 — GPU 设备丢失或验证错误
device.lost.then(info => {
  console.error('GPU 设备丢失:', info.message, info.reason);
});

// ⑥ 将 WebGPU 画布上下文绑定到设备
const canvas = document.querySelector('canvas');
const context = canvas.getContext('webgpu');
const format = navigator.gpu.getPreferredCanvasFormat(); // 'bgra8unorm' 或 'rgba8unorm'
context.configure({
  device,
  format,
  alphaMode: 'premultiplied',
});
✅

最佳实践：始终使用 getPreferredCanvasFormat() 获取画布格式。使用原生格式可以避免 GPU 在写入帧缓冲时做额外的格式转换。

4创建缓冲区

GPU 缓冲区 (GPUBuffer) 是一维的原始字节存储，用于顶点数据、索引、Uniform 参数、存储结果等。你需要在创建时声明用途 (usage)，之后不能更改。

创建顶点缓冲区

// 顶点数据：位置 (x,y,z) + 颜色 (r,g,b)
const vertices = new Float32Array([
  // x,    y,    z,    r,   g,   b
   0.0,  0.5,  0.0,  1.0, 0.0, 0.0,  // 顶点 0: 红
  -0.5, -0.5,  0.0,  0.0, 1.0, 0.0,  // 顶点 1: 绿
   0.5, -0.5,  0.0,  0.0, 0.0, 1.0,  // 顶点 2: 蓝
]);

const vertexBuffer = device.createBuffer({
  label: 'triangle-vertices',           // 调试标签
  size: vertices.byteLength,            // 字节数
  usage: GPUBufferUsage.VERTEX | GPUBufferUsage.COPY_DST,  // 用途标志
  mappedAtCreation: true,               // 创建时立即映射（零拷贝写入）
});

// 写入数据
new Float32Array(vertexBuffer.getMappedRange()).set(vertices);
vertexBuffer.unmap();                   // 解除映射，GPU 可以访问

Buffer Usage 标志

  • VERTEX — 作为顶点属性输入
  • INDEX — 作为索引缓冲
  • UNIFORM — 作为 Uniform 缓冲区
  • STORAGE — 作为存储缓冲区（计算着色器读写）
  • COPY_SRC / COPY_DST — 作为拷贝源/目标
  • MAP_READ / MAP_WRITE — CPU 可映射读/写
⚠️

注意：MAP_READ/MAP_WRITE 不能与 VERTEX/INDEX/UNIFORM/STORAGE 组合。需要先 GPU 写入再 CPU 读取时，使用两个 buffer + copyBufferToBuffer。

5编写着色器（WGSL）

WGSL（WebGPU Shading Language）是 WebGPU 原生的着色器语言。语法介于 Rust 和 GLSL 之间，强类型，支持结构体、数组、纹理、采样器等。

顶点着色器 + 片元着色器

// shader.wgsl

// ─── 结构体定义 ───
struct VertexInput {
  @location(0) position: vec3f,    // 顶点位置
  @location(1) color: vec3f,       // 顶点颜色
};

struct VertexOutput {
  @builtin(position) position: vec4f,  // 裁剪空间坐标（必须）
  @location(0) color: vec3f,           // 传递到片元着色器
};

struct Uniforms {
  modelViewProjection: mat4x4f,
  time: f32,
};

// ─── 绑定组 ───
@group(0) @binding(0) var<uniform> u: Uniforms;

// ─── 顶点着色器 ───
@vertex
fn vs_main(in: VertexInput) -> VertexOutput {
  var out: VertexOutput;
  out.position = u.modelViewProjection * vec4f(in.position, 1.0);
  out.color = in.color;
  return out;
}

// ─── 片元着色器 ───
@fragment
fn fs_main(in: VertexOutput) -> @location(0) vec4f {
  // 简单的颜色 + 时间动画
  let pulse = sin(u.time * 2.0) * 0.2 + 0.8;
  return vec4f(in.color * pulse, 1.0);
}

WGSL 关键语法速查

  • vec2f / vec3f / vec4f — 浮点向量；vec2i / vec2u — 整型/无符号
  • mat4x4f — 4×4 浮点矩阵
  • @location(N) — 管线中的属性/插值槽位
  • @builtin(position) — 系统内置：裁剪坐标、实例 ID 等
  • @group(N) @binding(N) — 绑定组中的资源槽位
  • var<uniform> / var<storage, read> / var<storage, read_write> — 缓冲区访问模式
  • textureSample(tex, sampler, uv) — 纹理采样

6设计渲染管线

渲染管线 (Render Pipeline) 是 WebGPU 中最重要的概念。它把着色器、顶点布局、混合模式、深度测试等所有状态打包成一个不可变的预编译对象，运行时切换零开销。

创建渲染管线

const pipeline = device.createRenderPipeline({
  label: 'triangle-pipeline',

  // ── 布局：Bind Group 的排布方式 ──
  layout: device.createPipelineLayout({
    bindGroupLayouts: [bindGroupLayout],  // 每个 @group 对应一个 layout
  }),

  // ── 顶点阶段 ──
  vertex: {
    module: shaderModule,
    entryPoint: 'vs_main',
    buffers: [{
      arrayStride: 6 * 4,   // 每个顶点的字节跨度: 6 floats × 4 bytes
      attributes: [
        { shaderLocation: 0, offset: 0,      format: 'float32x3' },  // position
        { shaderLocation: 1, offset: 3 * 4,  format: 'float32x3' },  // color
      ],
    }],
  },

  // ── 片元阶段 ──
  fragment: {
    module: shaderModule,
    entryPoint: 'fs_main',
    targets: [{
      format: format,  // 与 canvas.configure 的 format 一致
      blend: {         // Alpha 混合配置
        color: { srcFactor: 'src-alpha', dstFactor: 'one-minus-src-alpha', operation: 'add' },
        alpha: { srcFactor: 'one',       dstFactor: 'one-minus-src-alpha', operation: 'add' },
      },
      writeMask: GPUColorWrite.ALL,  // 写入 RGBA 所有通道
    }],
  },

  // ── 图元拓扑 ──
  primitive: {
    topology: 'triangle-list',    // 'triangle-strip' | 'line-list' | 'point-list'
    frontFace: 'ccw',             // 逆时针为正面
    cullMode: 'back',             // 剔除背面
  },

  // ── 深度/模板（可选）──
  depthStencil: {
    format: 'depth24plus',
    depthWriteEnabled: true,
    depthCompare: 'less',
  },

  // ── 多重采样 ──
  multisample: {
    count: 1,                     // 1 = 无 MSAA；4 = 4x MSAA
  },
});
💡

管线缓存：创建管线是异步的（内部做着色器编译）。可以使用 createRenderPipelineAsync() 或 PipelineCache 来避免首帧卡顿。

Bind Group Layout — 声明资源绑定契约

const bindGroupLayout = device.createBindGroupLayout({
  entries: [
    {
      binding: 0,
      visibility: GPUShaderStage.VERTEX | GPUShaderStage.FRAGMENT,
      buffer: { type: 'uniform' },
    },
    {
      binding: 1,
      visibility: GPUShaderStage.FRAGMENT,
      texture: { sampleType: 'float' },
    },
    {
      binding: 2,
      visibility: GPUShaderStage.FRAGMENT,
      sampler: { type: 'filtering' },
    },
  ],
});

7编码渲染通道

WebGPU 使用 CommandEncoder 录制 GPU 命令，然后一次性提交。录制期间不消耗 GPU 时间，提交后 GPU 执行。

完整的渲染帧

function renderFrame(time) {
  // ① 更新 Uniform 数据
  device.queue.writeBuffer(uniformBuffer, 0, uniformData);

  // ② 获取当前帧纹理（画布的后缓冲）
  const colorTexture = context.getCurrentTexture();

  // ③ 创建命令编码器
  const encoder = device.createCommandEncoder({ label: 'frame-encoder' });

  // ④ 开始渲染通道
  const pass = encoder.beginRenderPass({
    colorAttachments: [{
      view: colorTexture.createView(),   // 渲染目标
      loadOp: 'clear',                   // 清屏操作: 'clear' | 'load'
      storeOp: 'store',                  // 存储操作: 'store' | 'discard'
      clearValue: { r: 0.05, g: 0.05, b: 0.1, a: 1.0 },
    }],
    depthStencilAttachment: {
      view: depthTexture.createView(),
      depthLoadOp: 'clear',
      depthStoreOp: 'store',
      depthClearValue: 1.0,
    },
  });

  // ⑤ 绑定管线和资源
  pass.setPipeline(pipeline);
  pass.setVertexBuffer(0, vertexBuffer);
  pass.setBindGroup(0, uniformBindGroup);

  // ⑥ 绘制！
  pass.draw(3,      // 顶点数
            1,      // 实例数
            0,      // 第一个顶点
            0);     // 第一个实例

  // ⑦ 结束通道并提交
  pass.end();
  device.queue.submit([encoder.finish()]);

  requestAnimationFrame(renderFrame);
}

索引绘制（复用顶点）

// 索引缓冲
const indices = new Uint16Array([0, 1, 2,  2, 3, 0]);
const indexBuffer = device.createBuffer({
  size: indices.byteLength,
  usage: GPUBufferUsage.INDEX | GPUBufferUsage.COPY_DST,
  mappedAtCreation: true,
});
new Uint16Array(indexBuffer.getMappedRange()).set(indices);
indexBuffer.unmap();

// 渲染通道中
pass.setIndexBuffer(indexBuffer, 'uint16');
pass.drawIndexed(6);  // 6 个索引 → 2 个三角形

8计算着色器

计算着色器是 WebGPU 的杀手级特性。它绕过光栅化管线，直接在 GPU 上执行通用并行计算 — 矩阵乘法、粒子模拟、图像处理、神经网络推理……

WGSL 计算着色器示例：向量加法

// compute_add.wgsl
@group(0) @binding(0) var<storage, read>       a: array<f32>;
@group(0) @binding(1) var<storage, read>       b: array<f32>;
@group(0) @binding(2) var<storage, read_write> result: array<f32>;

@compute @workgroup_size(256)
fn main(@builtin(global_invocation_id) id: vec3u) {
  let i = id.x;
  if (i < arrayLength(&a)) {
    result[i] = a[i] + b[i];
  }
}

调度计算

// 创建计算管线（比渲染管线简单得多）
const computePipeline = device.createComputePipeline({
  layout: 'auto',
  compute: {
    module: computeShaderModule,
    entryPoint: 'main',
  },
});

// 录制计算命令
const encoder = device.createCommandEncoder();
const pass = encoder.beginComputePass();
pass.setPipeline(computePipeline);
pass.setBindGroup(0, computeBindGroup);
pass.dispatchWorkgroups(Math.ceil(dataLength / 256));  // 分派工作组
pass.end();
device.queue.submit([encoder.finish()]);
✅

Workgroup Size 选择：通常 256 或 512 是好的默认值。应是 GPU wave/warp 大小 (32 或 64) 的倍数。太小浪费 SIMD 通道，太大可能超出寄存器限制。

9纹理与采样器

纹理 (Texture) 是 GPU 上的 2D/3D 图像存储。配合采样器 (Sampler) 可以实现图像滤波、mipmap、各向异性过滤等。

从 ImageBitmap 加载纹理

// 创建纹理
const texture = device.createTexture({
  label: 'diffuse-texture',
  size: [image.width, image.height, 1],
  format: 'rgba8unorm',
  usage: GPUTextureUsage.TEXTURE_BINDING   // 着色器采样
       | GPUTextureUsage.COPY_DST          // 接受拷贝
       | GPUTextureUsage.RENDER_ATTACHMENT, // 可作为渲染目标
  mipLevelCount: 1,
});

// 上传图像数据
device.queue.copyExternalImageToTexture(
  { source: imageBitmap },          // 来源
  { texture },                       // 目标
  [image.width, image.height],       // 尺寸
);

// 创建采样器
const sampler = device.createSampler({
  magFilter: 'linear',       // 放大滤波
  minFilter: 'linear',       // 缩小滤波
  mipmapFilter: 'linear',    // Mipmap 滤波
  addressModeU: 'repeat',    // U 轴寻址模式
  addressModeV: 'repeat',    // V 轴寻址模式
  maxAnisotropy: 16,         // 各向异性过滤
});

在 WGSL 中采样纹理

@group(0) @binding(1) var          myTexture: texture_2d<f32>;
@group(0) @binding(2) var          mySampler: sampler;

@fragment
fn fs_main(@location(0) uv: vec2f) -> @location(0) vec4f {
  return textureSample(myTexture, mySampler, uv);
}

10Uniform 缓冲区

Uniform 缓冲区用于向着色器传递逐帧或逐对象的参数：变换矩阵、时间、光照参数等。所有线程共享同一份数据。

创建与绑定

// 定义 JS 侧数据结构（注意 16 字节对齐）
const uniformData = new Float32Array(16 + 4); // mat4 + padding
uniformData.set(mvpMatrix, 0);                // 偏移 0: MVP 矩阵
uniformData[16] = performance.now() / 1000;   // 偏移 64: time

const uniformBuffer = device.createBuffer({
  size: uniformData.byteLength,
  usage: GPUBufferUsage.UNIFORM | GPUBufferUsage.COPY_DST,
});

// 每帧更新
device.queue.writeBuffer(uniformBuffer, 0, uniformData);

// 创建 Bind Group
const bindGroup = device.createBindGroup({
  layout: pipeline.getBindGroupLayout(0),
  entries: [
    { binding: 0, resource: { buffer: uniformBuffer } },
  ],
});
⚠️

对齐规则：WGSL 的 mat4x4f 要求 16 字节对齐；vec4f 也是 16 字节。vec3f 虽然只有 12 字节，但仍然按 16 字节对齐。结构体的每个成员之间可能存在 padding。

11深度与模板测试

深度测试确保近处的物体遮挡远处的物体，是 3D 渲染的基础。模板测试可用于实现镜面反射、裁剪区域等高级效果。

创建深度纹理

const depthTexture = device.createTexture({
  size: [canvas.width, canvas.height],
  format: 'depth24plus',           // 24位深度 + 8位模板
  usage: GPUTextureUsage.RENDER_ATTACHMENT,
});

深度比较选项

  • 'less' — 深度值更小（更近）才通过（最常用）
  • 'less-equal' — 小于等于时通过
  • 'greater' — 反向深度（更适合大场景）
  • 'always' — 总是通过（禁用深度测试）
✅

反向深度 (Reversed-Z)：使用 'greater' 比较 + 清除值 0.0，可以显著提高远处物体的深度精度，减少 Z-fighting。这是 3D 引擎的常见优化。
