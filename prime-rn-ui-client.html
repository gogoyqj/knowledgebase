项目概述

Prime Agent React Native 客户端是一个通过 socket-transfer relay 与远程 Agent 守护进程通信的移动端应用。 采用 Consumer → Transport → Client → EventBridge → Store 分层架构， 利用 Metro bundler 的 .native.ts 后缀解析实现平台隔离，Web 代码零侵入。

router Relay 通信

通过 socket-transfer Consumer 连接 relay 服务器，订阅 Agent 守护进程的 Connection， 建立点对点双向 Transport 通道。

layers 平台隔离

Metro bundler 配置 .native.ts 优先级解析， agent-service.js 自动映射到原生实现， 无需手动修改 import 路径。

sync_alt 事件驱动

EventBridge 将后端推送事件翻译为 Store 变更， React 组件通过 useSyncExternalStore 订阅自动更新 UI。

settings Metro 平台解析

自定义 resolveRequest 让 Metro 自动优先查找 .native.ts 后缀文件，实现平台隔离。 

// metro.config.cjs
resolveRequest(context, moduleName, platform) {
  // .js → 去掉后缀，让 Metro 重新解析
  if (moduleName.startsWith(".") && moduleName.endsWith(".js"))
    moduleName = moduleName.slice(0, -3);

  // 优先查找 .native.ts, 再找 .ios.ts / .android.ts
  for (const suffix of [".native", `.${platform}`]) {
    for (const ext of [".ts", ".tsx", ".js"]) {
      try {
        return context.resolveRequest(context, moduleName + suffix + ext, platform);
      } catch {}
    }
  }
}

关键设计决策

hourglass_top 懒加载 Store

问题：Store 构造函数访问 agentService.client， 但 RN 中 client 在 subscribeToConnection() 后才可用。

方案：index.native.ts 导出未初始化的 let 变量，在 initializeStores() 中赋值。模块加载时只创建无依赖的 ConnectionStore 和 ToastStore。

autorenew EventBridge 重连

问题：每次 subscribeToConnection() 创建新的 AgentConnectionClient，旧 EventBridge 仍在监听已废弃的 client。

方案：connectEventBridge() 返回 cleanup 函数， initializeStores() 每次调用时先 cleanup 再重连。 保证事件始终路由到当前活跃的 client。

power_settings_new 异步订阅

问题：subscribeToConnection() 原本是同步的， Transport 未就绪时 UI 就开始发送命令，导致 "Transport not connected" 错误。

方案：改为 async，返回 Promise， 在 transport.onOpen() 时 resolve。 App.tsx 中 await subscribeToConnection() 后才初始化 Store。

class RnService 类设计

问题：最初设计为工厂函数 + configureAgentService，存在模块绑定时序问题。

方案：改为 class RnService implements AgentService， 在 agent-service.native.ts 中 new RnService() 导出固定实例。所有 import 同一个引用，无时序依赖。

Hermesc: Couldn't determine location Monorepo 中 node_modules 提升到根目录，Gradle 默认路径 %OS-BIN%/hermesc 解析失败 在 app/build.gradle 的 react {} 块中显式设置：
hermesCommand = file("../../../../node_modules/react-native/sdks/hermesc/osx-bin/hermesc").absolutePath

android:networkSecurityConfig="@xml/network_security_config"
Debug APK unable to load script after release build 构建 app-release.apk 后再运行 npm run mobile:android，debug APK 无法加载 Metro bundle。 根因是 network_security_config.xml 只允许了 relay 服务器的明文通信，未允许 localhost，导致 debug 模式连接 Metro（localhost:8081）被 Android 网络安全策略拦截。 在 network_security_config.xml 中同时添加 localhost 和 10.0.2.2 域名许可：

Android 网络隔离详解：
Android 模拟器运行在独立虚拟网络中，localhost / 127.0.0.1 指向模拟器自身回环，非宿主机。 Google 提供特殊别名 10.0.2.2 映射到宿主机的 127.0.0.1。 iOS 模拟器与宿主机共享网络栈，localhost 直接可用。

真机调试：确保手机与开发机在同一局域网，使用开发机局域网 IP（如 ws://192.168.1.x:3456）。

ws 模块 Stub：
socket-transfer 内部依赖 Node.js 的 ws 包，RN 环境没有此模块会直接报错。 通过 Metro resolveRequest 将 "ws" 映射到一个空的 JS 文件（emptyModule.js）， 使 import 不报错但不执行任何操作。RN 中 Consumer 使用全局 WebSocket API，不走 ws。

extension 使用 C++ 扩展 Native Module（TurboModule）

TurboModules 通过 JSI 实现 JS ↔ C++ 同步调用，适合高性能计算、加密、图像处理等场景。 以下是一个最小 C++ TurboModule 的完整示例。

步骤 1：定义 JS Spec（Codegen 输入）

// native/NativeMathModule.ts
import { TurboModule } from "react-native";
import { TurboModuleRegistry } from "react-native";

export interface Spec extends TurboModule {
  // 同步方法 — JS 直接拿到返回值，无 Bridge 异步开销
  fibonacci(n: number): number;

  // 异步方法 — 返回 Promise
  factorialAsync(n: number): Promise<number>;

  // 常量 — 在 Native 侧定义，JS 侧只读
  readonly PI_SQUARED: number;
}

export default TurboModuleRegistry.getEnforcing<Spec>("MathModule");

步骤 2：C++ 实现

// cpp/NativeMathModule.h
#pragma once
#include "NativeMathModuleSpec.h"  // Codegen 生成

namespace facebook::react {

class NativeMathModule : public NativeMathModuleSpecCxx {
public:
  NativeMathModule(std::shared_ptr<CallInvoker> jsInvoker);

  // 同步方法 — 直接在 JS 线程执行，返回值立即可用
  double fibonacci(double n) override;

  // 异步方法 — 返回 jsi::Value (Promise)
  jsi::Value factorialAsync(jsi::Runtime& rt, double n) override;

  // 常量
  jsi::Value getConstants(jsi::Runtime& rt) override;
};

} // namespace facebook::react
// cpp/NativeMathModule.cpp
#include "NativeMathModule.h"
#include <future>

namespace facebook::react {

NativeMathModule::NativeMathModule(std::shared_ptr<CallInvoker> jsInvoker)
    : NativeMathModuleSpecCxx(std::move(jsInvoker)) {}

double NativeMathModule::fibonacci(double n) {
  if (n <= 1) return n;
  double a = 0, b = 1;
  for (int i = 2; i <= (int)n; i++) {
    double tmp = a + b;
    a = b;
    b = tmp;
  }
  return b;
}

jsi::Value NativeMathModule::factorialAsync(jsi::Runtime& rt, double n) {
  // 创建 Promise 并在后台线程执行
  auto promise = Promise::create(rt);
  auto result = promise.getValue(rt);

  std::async(std::launch::async, [this, n, promise = std::move(promise)]() mutable {
    double acc = 1;
    for (int i = 2; i <= (int)n; i++) acc *= i;
    promise.resolve(acc);  // 回到 JS 线程 resolve
  });

  return result;
}

jsi::Value NativeMathModule::getConstants(jsi::Runtime& rt) {
  auto obj = jsi::Object(rt);
  obj.setProperty(rt, "PI_SQUARED", M_PI * M_PI);
  return obj;
}

} // namespace facebook::react

C++ vs Java/ObjC NativeModule 选择：
• C++ TurboModule — 跨平台共享一份代码，同步调用，适合计算密集型（加密、图像处理、数学运算）
• Java/ObjC Module — 需要访问平台 API（蓝牙、相机、文件系统），每平台各写一份
• 混合方案 — C++ 核心逻辑 + Java/ObjC 薄包装层，兼顾跨平台和平台能力
