Key: DaemonAgentConnection.attach() creates a new instance every call (no cache). Each instance has a unique clientId (UUID) but shares the same underlying DaemonClient (Unix socket).
Anti-duplicate guard: sessionEventListeners Map (keyed by sessionId) prevents duplicate event broadcast listeners when the same session entry is disposed and re-created.

Communication Flow

①
User Sends a Message
1
Frontend: handlePrompt(text)
Calls agentService.client.prompt(text) — sends RPC over WebSocket
2
DaemonBridge: handleMessage(msg, transport)
Looks up sessions.get(sessionId) → existing entry → dispatch(entry, msg)
3
DaemonAgentConnection: connection.prompt(text)
Sends command via DaemonClient → Unix Socket → Daemon Process
4
Daemon: processes prompt, broadcasts message_update events
Events flow back: Daemon → Unix Socket → DaemonClient → DaemonAgentConnection listeners
5
DaemonBridge: subscription callback fires
Reads sessionSubscribers.get(sessionId) → broadcasts to all subscribed Transports (tabs)
6
Frontend: EventBridge processes session_event
messageStore.onMessageUpdate() → React re-renders with streaming content
②
Create Session
1
sessionStore.createSession(name, cwd)
Sends create command (daemon-level) → Daemon creates session → returns { activeSessionId, sessionFile }
2
messageStore.switchSession(newId)
Clears message cache, sets active session ID
3
sessionStore.setActiveSession(newId)
Sends switch_session to daemon (daemon-level, no entry created). Daemon may broadcast session_resynced — but no listener exists yet, event is lost.
4
messageStore.fetchHistory()
Sends get_messages (session-scoped) → creates entry + listener → connection.getMessages() → onHistoryMessages()
③
Switch Session (A → B)
1
handleSelectSession(sessionFile)
messageStore.switchSession(B) → sessionStore.setActiveSession(B)
2
sessionStore.setActiveSession(B)
Sends switch_session to daemon → subscribeTransport(transport, B) → unsubscribes from A
3
If A has no more subscribers
unsubscribeTransport → entry.detachEvents() + connection.dispose() + sessions.delete(A)
4
fetchHistory() for B
Sends get_messages → creates entry for B → onHistoryMessages()

Design Decisions

!
Anti-Duplicate: sessionEventListeners
ProblemSolution
Each attach() creates a new DaemonAgentConnection. When a session entry is disposed (last subscriber leaves) and later re-created, a new listener is added to the new connection instance. If events arrive before disposal, they accumulate. sessionEventListeners Map (keyed by sessionId) tracks whether a listener is registered. detachEvents() closure cleans up both the listener and the Map entry on disposal. Next create can safely re-register.
i
Transport Subscription Lifecycle
EventAction
Transport sends session-scoped command subscribeTransport(transport, sessionId) — adds to sessionSubscribers
Transport switches to different session unsubscribeTransport from old → subscribeTransport to new
Transport disconnects handleDisconnect → unsubscribeTransport from current session
Last subscriber leaves a session detachEvents() + connection.dispose() + sessions.delete()
✓
Command Routing
Command TypeRoutingEntry Created?
list · kill · rename · create · switch_session · browse_path Daemon-level → executeDaemonCommand() No
get_messages · prompt · get_state · ... Session-scoped → dispatch(entry, msg) Yes (if not exists)
Session-scoped commands auto-create a session entry + listener on first access. The entry is disposed when the last subscriber leaves.

Electron IPC Layer

⚡
Dual-Mode Architecture
Web Mode
WsTransport → WebSocket → Node.js server → DaemonBridge → Daemon
Multiple tabs, each with own WS connection. DaemonBridge runs in Node.js process.
Electron Mode
IpcTransport → ipcRenderer → Electron main process → DaemonBridge → Daemon
Single window per app. DaemonBridge runs in Electron main process.
Shared code: React UI, Stores, EventBridge, AgentConnectionClient are identical in both modes. Only the Transport and AgentService implementations differ.
⇄
IPC Communication Flow
1
Preload script exposes ElectronAgentBridge
contextBridge.exposeInMainWorld('agentBridge', { sendCommand, onEvent, onClose, listSessions, killSession })
2
Renderer: createIpcTransport(bridge)
Creates IpcTransport wrapping the bridge. send() → bridge.sendCommand() → ipcRenderer.invoke('agent:command', data)
3
Main process: ipcMain.handle('agent:command', handler)
Receives command → routes to DaemonBridge.handleMessage() → returns response
4
Main process: mainWindow.webContents.send('agent:event', event)
Daemon events pushed to renderer via webContents.send()
5
Renderer: bridge.onEvent(callback) receives events
ipcRenderer.on('agent:event', callback) → dispatches to AgentConnectionClient → EventBridge → Stores
⌘
IPC vs WebSocket — Interface Mapping
OperationWeb Mode (WsTransport)Electron Mode (IpcTransport)
Send command ws.send(JSON.stringify(msg)) ipcRenderer.invoke('agent:command', msg)
Receive events ws.onmessage = (e) => JSON.parse(e.data) ipcRenderer.on('agent:event', (e, data) => data)
Connection close ws.onclose ipcRenderer.on('agent:close', callback)
List sessions RPC: request('list') Direct IPC: bridge.listSessions()
Kill session RPC: request('kill') Direct IPC: bridge.killSession(id)
Browse dirs browse_path — DaemonBridge handles fs.readdir in both modes
🔌
AgentService Interface
MethodWebServiceRpcService
listSessions() client.request('list') bridge.listSessions() (direct IPC)
killSession(id) client.request('kill') bridge.killSession(id) (direct IPC)
createSession(name?, cwd?) client.createSession() (same in both)
browsePath(path?) client.browsePath() (same in both)
subscribe(listener) client.subscribe() (same in both)
Electron advantage: listSessions() and killSession() bypass the RPC layer and go directly through IPC for lower latency. All other commands use the same AgentConnectionClient RPC protocol.

CWD Browser (Directory Picker)

📁
Implementation
1
User clicks 📁 button in AgentSidebar
Toggles inline directory browser component
2
browsePath(path) → daemon-bridge
Daemon-level command: fs.readdir(path, { withFileTypes: true }) → returns { path, dirs[] }
3
User navigates and selects directory
Each click updates CWD input in real-time + fetches subdirectories
Why not File System Access API? showDirectoryPicker() returns a FileSystemDirectoryHandle — security restrictions prevent retrieving the full filesystem path. A bridge-side command (browse_path) is required. Works identically in both Web mode (Node.js server) and Electron mode (main process).
