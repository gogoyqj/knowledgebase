Webpack 是什么？

Webpack 是一个现代 JavaScript 应用的静态模块打包工具。它将项目中的所有资源（JS、CSS、图片、字体等） 视为模块，通过分析模块间的依赖关系，构建出一个或多个优化后的 bundle。

lightbulb
Webpack 的核心设计理念是一切皆模块。不仅 JS 文件是模块，CSS、图片、字体等都可以通过 Loader 转换后作为模块处理。

五大核心概念

input Entry

构建的入口起点。Webpack 从 Entry 开始递归分析依赖，构建完整的依赖图。

output Output

打包产物的输出配置。定义输出文件名、路径，以及如何命名 chunk 和资源。

transform Loader

模块转换器。Webpack 只能处理 JS/JSON，Loader 让 Webpack 能处理其他类型的文件。

extension Plugin

构建流程扩展。Plugin 可以介入构建的任何阶段，执行更广泛的任务（优化、资源管理、注入环境变量）。

tune Mode

内置优化策略。development / production / none，自动启用对应的优化插件。

核心对象详解

📦 Compiler

Compiler 是 Webpack 的核心引擎，代表完整的构建环境配置。它是一个全局单例， 在整个生命周期中只创建一次。Compiler 持有所有配置信息，并负责创建 Compilation 实例。

📋 Compilation

Compilation 代表一次具体的构建过程。每次文件变化触发重新编译时，都会创建一个新的 Compilation 实例。 它负责：模块解析、依赖收集、Chunk 优化、资源生成。

🧩 Module

Module 是 Webpack 中的基本处理单元。每个文件经过 Loader 处理后都被抽象为一个 Module。 Module 记录了文件的内容、类型、依赖关系等信息。

🔗 Dependency

Dependency 描述模块间的依赖关系。当解析 import / require 时， Webpack 会创建 Dependency 对象，记录被依赖模块的信息。

📄 Chunk

Chunk 是一组 Module 的集合，是代码分割的基本单位。一个 Entry 通常对应一个 Chunk， 通过动态 import 或 splitChunks 可以产生额外的 Chunk。

📁 Asset

Asset 是最终输出的文件资源（.js、.css、图片等）。Chunk 经过代码生成后产出 Asset。

构建生命周期总览

Webpack 的构建过程由一系列生命周期钩子（Hooks）驱动。 Plugin 通过在特定钩子上注册回调函数来介入构建流程。整个生命周期分为三大阶段： 初始化、编译、输出。

1. 初始化阶段

读取配置 → 合并默认配置 → 创建 Compiler 实例 → 初始化 Plugin

2. 编译阶段

创建 Compilation → 从 Entry 开始编译 → 递归解析依赖 → 使用 Loader 转换模块

3. 优化与输出阶段

Chunk 分割优化 → 代码压缩 → 生成 Asset → 写入文件系统

关键钩子详解

以下是 Plugin 开发中最常用的钩子，按构建顺序排列：

🔧 Compiler 钩子（全局，只触发一次）

// Compiler 生命周期钩子
compiler.hooks.initialize          // 初始化完成
compiler.hooks.run                 // 开始编译（异步）
compiler.hooks.compile             // 开始编译（同步）
compiler.hooks.compilation         // 创建 Compilation 实例
compiler.hooks.make               // 开始构建依赖图（异步）
compiler.hooks.emit               // 资源写入前（异步，可修改 Asset）
compiler.hooks.afterEmit           // 资源已写入（异步）
compiler.hooks.done               // 构建完成（异步）
compiler.hooks.failed              // 构建失败
compiler.hooks.watchRun            // watch 模式下每次重新编译
compiler.hooks.watchClose          // watch 模式关闭
compiler.hooks.infrastructureLog   // 基础设施日志

📋 Compilation 钩子（每次编译触发一次）

// Compilation 生命周期钩子
compilation.hooks.buildModule       // 模块开始构建前（可修改 Loader 参数）
compilation.hooks.succeedModule    // 模块构建成功
compilation.hooks.failModule       // 模块构建失败
compilation.hooks.finishModules    // 所有模块构建完成

compilation.hooks.seal             // 封装开始（不可再添加模块）
compilation.hooks.optimize         // 优化开始
compilation.hooks.optimizeChunks    // Chunk 优化（Tree Shaking 在此）
compilation.hooks.optimizeAssets    // Asset 优化（压缩在此）

compilation.hooks.processAssets     // 处理 Asset（推荐，取代 emit）

Compiler vs Compilation

🏗️ Compiler

  • 全局唯一实例
  • 代表完整的构建环境
  • 包含 webpack 完整配置
  • 生命周期贯穿整个构建
  • Plugin 在此处注册

📋 Compilation

  • 每次编译创建新实例
  • 代表一次具体的构建过程
  • 包含当次构建的模块和依赖
  • watch 模式下每次变化都重建
  • Module 和 Chunk 在此创建
extension

Plugin 是什么？

Plugin 是 Webpack 的支柱。Webpack 自身就是由一系列内置 Plugin 构建的。 Plugin 可以介入构建的任何阶段，执行各种任务：打包优化、资源管理、环境变量注入等。

lightbulb
Plugin vs Loader：Loader 是文件级别的转换（将 A 转为 B），Plugin 是构建级别的扩展（介入整个构建流程）。Plugin 的能力远大于 Loader。
architecture

Plugin 基本结构

一个 Webpack Plugin 必须满足以下条件：

  • 是一个带有 apply(compiler) 方法的类
  • 在 apply 方法中通过 compiler.hooks.xxx.tap() 注册钩子回调
  • 插件名称必须使用驼峰式命名，且在 apply 方法中不能使用箭头函数
// 最简 Plugin 模板
class MyPlugin {
  // 必须实现 apply 方法
  apply(compiler) {
    // 获取插件名称，用于日志标识
    const pluginName = MyPlugin.name

    // 在 compiler 的 done 钩子上注册回调
    compiler.hooks.done.tap(pluginName, (stats) => {
      console.log('构建完成！')
      console.log(`耗时: ${stats.endTime - stats.startTime}ms`)
    })
  }
}

// 使用
module.exports = {
  plugins: [new MyPlugin()]
}

实战：文件清单 Plugin

一个实用的 Plugin，在构建完成后生成包含所有输出文件的 manifest.json：

class ManifestPlugin {
  apply(compiler) {
    const pluginName = 'ManifestPlugin'

    // 使用 emit 钩子 —— 资源写入前的最后机会
    compiler.hooks.emit.tapAsync(pluginName, (compilation, callback) => {
      // 获取所有输出资源
      const manifest = {
        name: 'My App',
        buildTime: new Date().toISOString(),
        files: {}
      }

      // 遍历 compilation.assets 获取所有输出文件
      for (const [name, asset] of Object.entries(compilation.assets)) {
        manifest.files[name] = {
          size: asset.size(),
          // 对 JS/CSS 计算内容 hash
          hash: compilation.getPath('[contenthash]', { filename: name })
        }
      }

      // 将 manifest.json 添加到输出资源
      const json = JSON.stringify(manifest, null, 2)
      compilation.assets['manifest.json'] = {
        source() { return json },
        size() { return json.length }
      }

      callback()
    })
  }
}

实战：构建通知 Plugin

使用 Compiler 的多个钩子，在构建关键阶段输出日志：

class BuildNotifierPlugin {
  constructor(options = {}) {
    this.options = {
      verbose: false,
      ...options
    }
  }

  apply(compiler) {
    const name = 'BuildNotifierPlugin'
    const startTime = new Map()

    // 1. 编译开始
    compiler.hooks.compile.tap(name, () => {
      console.log('🚀 编译开始...')
      startTime.set('compile', Date.now())
    })

    // 2. 单个模块构建完成
    compiler.hooks.compilation.tap(name, (compilation) => {
      compilation.hooks.succeedModule.tap(name, (module) => {
        if (this.options.verbose) {
          console.log(`  ✅ ${module.resource}`)
        }
      })
    })

    // 3. 所有资源即将写入
    compiler.hooks.emit.tapAsync(name, (compilation, callback) => {
      const files = Object.keys(compilation.assets)
      console.log(`📦 生成 ${files.length} 个资源文件`)
      callback()
    })

    // 4. 构建完成
    compiler.hooks.done.tap(name, (stats) => {
      const duration = Date.now() - startTime.get('compile')
      if (stats.hasErrors()) {
        console.log((`❌ 构建失败 (${duration}ms)`))
      } else {
        console.log(`✅ 构建成功！(${duration}ms)`)
      }
    })

    // 5. 构建失败
    compiler.hooks.failed.tap(name, (error) => {
      console.error('💥 构建错误:', error.message)
    })
  }
}

实战：修改资源内容 Plugin

使用 processAssets 钩子（推荐方式）修改输出资源：

class BannerPlugin {
  constructor(options) {
    this.banner = options.banner || ''
  }

  apply(compiler) {
    const name = 'BannerPlugin'
    const { Compilation } = compiler.webpack

    compiler.hooks.compilation.tap(name, (compilation) => {
      // processAssets 是处理 Asset 的推荐钩子（取代 emit）
      // PROCESS_ASSETS_STAGE_ADDITIONS = 100 —— 添加资源阶段
      compilation.hooks.processAssets.tap(
        {
          name,
          stage: Compilation.PROCESS_ASSETS_STAGE_ADDITIONS
        },
        () => {
          for (const [name, asset] of Object.entries(compilation.assets)) {
            // 只处理 .js 文件
            if (name.endsWith('.js')) {
              const original = asset.source()
              const updated = `/** ${this.banner} */\n${original}`

              compilation.updateAsset(name, {
                source() { return updated },
                size() { return updated.length }
              })
            }
          }
        }
      )
    })
  }
}

// 使用
new BannerPlugin({
  banner: 'MyApp v1.0.0 | Built: 2024-01-15'
})

实战：自动外链 CDN Plugin

一个更复杂的 Plugin，自动将匹配的依赖模块替换为 CDN 外链：

class ExternalCDNPlugin {
  constructor(options) {
    // options.externals = { react: 'React', 'react-dom': 'ReactDOM' }
    this.externals = options.externals || {}
  }

  apply(compiler) {
    const name = 'ExternalCDNPlugin'

    // 使用 compiler.hooks.externals 钩子
    compiler.hooks.compile.tap(name, (params) => {
      const normalModuleFactory = params.normalModuleFactory

      // 拦截模块解析
      normalModuleFactory.hooks.resolve.tapAsync(name, (resolveData, callback) => {
        const request = resolveData.request

        if (this.externals[request]) {
          // 标记为外部依赖
          resolveData.dependencies.forEach(dep => {
            dep.setResourceIdentifier(`external:${request}`)
          })
        }

        callback()
      })
    })

    // 更实用的方式：直接配置 externals + 生成 script 标签
    compiler.hooks.compilation.tap(name, (compilation) => {
      compilation.hooks.processAssets.tap(
        { name, stage: compiler.webpack.Compilation.PROCESS_ASSETS_STAGE_SUMMARIZE },
        () => {
          // 在 HTML 中注入 CDN script 标签（需配合 html-webpack-plugin）
          const htmlFile = Object.keys(compilation.assets).find(f => f.endsWith('.html'))
          if (!htmlFile) return

          let html = compilation.assets[htmlFile].source()
          const scripts = Object.entries(this.externals)
            .map(([, url]) => `<script src="${url}"></script>`)
            .join('\n  ')

          html = html.replace('</head>', `  ${scripts}\n</head>`)

          compilation.updateAsset(htmlFile, {
            source() { return html },
            size() { return html.length }
          })
        }
      )
    })
  }
}

// 使用
new ExternalCDNPlugin({
  externals: {
    react: 'https://unpkg.com/react@18/umd/react.production.min.js',
    'react-dom': 'https://unpkg.com/react-dom@18/umd/react-dom.production.min.js'
  }
})

Tapable — Webpack 的事件系统

Tapable 是 Webpack 的插件架构核心，类似于 Node.js 的 EventEmitter，但功能更强大。 它提供了多种类型的 Hook，支持同步/异步、串行/并行/瀑布/熔断等执行模式。 

// Tapable 核心 API
const { SyncHook, AsyncSeriesHook, AsyncParallelHook } = require('tapable')

// 注册回调（tap = 拴住，即"挂钩子"）
hook.tap(name, callback)            // 同步注册
hook.tapAsync(name, callback)        // 异步注册（回调风格）
hook.tapPromise(name, callback)      // 异步注册（Promise 风格）

// 触发钩子
hook.call(...args)                   // 同步触发
hook.callAsync(...args, callback)    // 异步触发
hook.promise(...args)                // Promise 触发
view_list

Hook 类型一览

🔗 SyncHook

同步串行。注册的回调按顺序依次执行，返回值被忽略。

🔗 SyncBailHook

同步熔断。回调返回非 undefined 时立即停止后续回调。

🔗 SyncWaterfallHook

同步瀑布。每个回调的返回值作为下一个回调的第一个参数。

🔗 SyncLoopHook

同步循环。回调返回 true 时重复执行当前回调。

⏳ AsyncParallelHook

异步并行。所有回调并行执行，全部完成后触发。

⏳ AsyncSeriesHook

异步串行。回调按顺序依次执行，前一个完成后才执行下一个。

⏳ AsyncSeriesBailHook

异步串行熔断。串行执行，回调返回非 undefined 时停止。

⏳ AsyncSeriesWaterfallHook

异步串行瀑布。串行执行，返回值传给下一个回调。

手写简版 Tapable

理解 Tapable 的核心原理——维护一个回调列表，在触发时按特定模式执行：

// 简版 SyncHook 实现
class SyncHook {
  constructor(args = []) {
    this.args = args       // 参数名称列表（仅用于文档）
    this.taps = []          // 注册的回调列表
  }

  // 注册回调
  tap(name, callback) {
    this.taps.push({ name, callback })
  }

  // 触发所有回调（串行执行）
  call(...args) {
    for (const tap of this.taps) {
      tap.callback(...args)
    }
  }
}

// 简版 SyncBailHook 实现
class SyncBailHook {
  constructor(args = []) {
    this.taps = []
  }

  tap(name, callback) {
    this.taps.push({ name, callback })
  }

  // 熔断：回调返回非 undefined 时停止
  call(...args) {
    for (const tap of this.taps) {
      const result = tap.callback(...args)
      if (result !== undefined) return result
    }
  }
}

// 简版 SyncWaterfallHook 实现
class SyncWaterfallHook {
  constructor(args = []) {
    this.taps = []
  }

  tap(name, callback) {
    this.taps.push({ name, callback })
  }

  // 瀑布：返回值作为下一个回调的第一个参数
  call(...args) {
    let [first, ...rest] = args
    for (const tap of this.taps) {
      const result = tap.callback(first, ...rest)
      if (result !== undefined) first = result
    }
    return first
  }
}

// ─── 使用示例 ───
const hook = new SyncHook(['name', 'age'])

hook.tap('PluginA', (name, age) => {
  console.log(`A: ${name} is ${age}`)
})
hook.tap('PluginB', (name, age) => {
  console.log(`B: ${name} is ${age}`)
})

hook.call('Alice', 25)
// 输出: A: Alice is 25
// 输出: B: Alice is 25
