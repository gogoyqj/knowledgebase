什么是 React Fiber？

React Fiber 是 React 16 引入的全新协调引擎（Reconciliation Engine），是对 React 核心算法的完全重写。 它的得名来自于 Fiber Tree（纤程树）— 每个 React 元素被表示为一个 FiberNode， 它们组成了一棵链表树，取代了旧版的递归 Virtual DOM diff。

compare_arrows

Stack Reconciler vs Fiber Reconciler

close Stack Reconciler（React ≤15）

  • 使用递归遍历 Virtual DOM
  • 一旦开始就无法中断
  • 大型更新会阻塞主线程数十毫秒
  • 导致动画卡顿、输入延迟
  • 调度粒度：整个组件子树

check Fiber Reconciler（React ≥16）

  • 使用链表遍历，支持遍历暂停
  • 可将工作拆分为多个时间片
  • 利用 requestIdleCallback 空闲调度
  • 支持优先级：高优任务可打断低优
  • 调度粒度：单个 Fiber 节点

Fiber 节点数据结构

每个 FiberNode 是一个 JavaScript 对象，包含三个核心指针构成链表树：

// 简化的 FiberNode 结构
type FiberNode = {
  // 身份标识
  tag:         FiberTag,       // FunctionComponent | ClassComponent | HostComponent ...
  type:        any,            // 组件函数/类 或 DOM 标签名 "div"
  key:         string | null,

  // 链表指针 — 这就是 "Fiber" 的核心结构
  child:       FiberNode | null,   // → 第一个子节点
  sibling:     FiberNode | null,   // → 下一个兄弟节点
  return:      FiberNode | null,   // → 父节点

  // 状态
  pendingProps:  Props,
  memoizedProps: Props,         // 上一次渲染的 props
  memoizedState: any,           // 上一次渲染的 state / hook 链表
  updateQueue:   UpdateQueue,    // 待处理的更新队列

  // 副作用
  flags:         Flags,          // Placement | Update | Deletion ...
  lanes:         Lanes,          // 优先级车道（Scheduler 优先级模型）
  alternate:     FiberNode,      // 双缓冲：current ↔ workInProgress
}
┌──────────┐ │ App │ ← Root Fiber │ (Fiber) │ └────┬─────┘ │ child ┌────▼─────┐ │ Header │ │ (Fiber) │ └────┬─────┘ ┌────────┼────────┐ child│ │sibling │ ┌─────▼──┐ ┌──▼─────┐ │ Logo │ │ Nav │ │(Fiber) │ │(Fiber) │ └────────┘ └──┬─────┘ ┌────┼────┐ child│ │ │sibling ┌─────▼┐ ┌▼────┐ ┌──────┐ │ Link │ │Link │ │ Link │ └──────┘ └─────┘ └──────┘ child → sibling → sibling 形成链表遍历 DFS 深度优先：child 优先，无 child 则 sibling，无 sibling 则 return

双缓冲（Double Buffering）与时间切片

Fiber 引入了两棵 Fiber 树交替工作，类似图形学中的双缓冲：

  • current tree — 当前屏幕上显示的 Fiber 树
  • workInProgress tree — 正在后台构建的新 Fiber 树
  • 更新完成后，workInProgress 变成 current，旧的 current 被回收
  • alternate 指针在两棵树的对应节点之间建立映射

时间切片（Time Slicing） 工作流程：

// React 的工作循环（简化）
function workLoop(deadline: Deadline) {
  // 1. 有下一个工作单元 && 当前帧还有剩余时间
  while (nextUnitOfWork !== null && !shouldYield()) {
    nextUnitOfWork = performUnitOfWork(nextUnitOfWork);
  }

  // 2. 时间用尽，让出主线程（让浏览器处理用户输入、动画）
  if (nextUnitOfWork !== null) {
    requestIdleCallback(workLoop);  // 空闲时继续
  } else {
    commitRoot();                   // 3. 全部完成，一次性提交到 DOM
  }
}
lightbulb
关键点：Fiber 把渲染分为两个阶段 —— Render 阶段（可中断，构建 workInProgress 树 + Diff）和 Commit 阶段（不可中断，一次性应用 DOM 变更）。 这就是为什么 useEffect 的执行时机在 DOM 更新之后。
priority_high

优先级调度（Lane 模型）

React 使用 Lane（车道） 位掩码模型来管理优先级，取代了早期的 expirationTime：

SyncLane — 同步（点击事件） InputContinuousLane — 连续输入（拖拽） DefaultLane — 默认（setState） TransitionLane — 过渡（useTransition） IdleLane — 空闲（离屏更新）

高优先级的 Lane 可以打断正在处理的低优先级工作，这就是 React 18 并发特性的底层基础。

rule

为什么 Hooks 不能在循环或条件中调用？

核心原因：React 依靠 Hook 的调用顺序 来将每个 Hook 与正确的 state 关联。 这不是任意规定，而是由 Hooks 的底层数据结构决定的。

底层数据结构：链表

每个函数组件的 Fiber 节点上有一个 memoizedState 字段， 它指向一个 单向链表，链表的每个节点代表一次 Hook 调用：

// Fiber 上的 Hook 链表
fiber.memoizedState →
  ┌─────────────────────┐     ┌─────────────────────┐     ┌──────────────────┐
  │ useState('Alice')   │     │ useEffect(fn)       │     │ useState(0)      │
  │                     │     │                     │     │                  │
  │ memoizedState:      │ ──▶ │ memoizedState:      │ ──▶ │ memoizedState:   │
  │   'Alice'           │     │   { deps, effect }  │     │   0              │
  │ next: ──────────────│────▶│ next: ──────────────│────▶│ next: null       │
  └─────────────────────┘     └─────────────────────┘     └──────────────────┘
         Hook #1                     Hook #2                     Hook #3

React 通过按调用顺序逐一匹配链表节点，为每次 useState / useEffect 分配对应的节点。

bug_report

如果在条件中调用会怎样？

// ❌ 错误示例 — 条件调用 Hook
function Form({ showName }) {
  const [email, setEmail] = useState('');   // Hook #1

  if (showName) {
    const [name, setName] = useState(''); // Hook #2 — 条件性!
  }

  const [age, setAge] = useState(0);     // Hook #3
}

首次渲染 showName = true

链表: [email] → [name] → [age] #1 #2 #3

重渲染 showName = false

链表: [email] → [name] → [age] #1 #2 #3 但 useState 调用只有 2 次: 调用 #1 → 匹配节点 [email] ✅ 调用 #2 → 匹配节点 [name] ❌ 期望 age!
warning
结果：useState(0) 拿到了 name 的 state！ setName 更新的是 age 的位置。 整个组件状态全面错乱，且极难调试。
check_circle

正确的替代方案

// ✅ 正确：Hook 始终调用，内部做条件判断
function Form({ showName }) {
  const [email, setEmail] = useState('');
  const [name, setName]     = useState('');   // 始终调用
  const [age, setAge]       = useState(0);     // 始终调用

  // 在 effect 内部做条件
  useEffect(() => {
    if (showName) {
      syncNameToServer(name);
    }
  }, [showName, name]);

  return showName
    ? <NameField value={name} onChange={setName} />
    : null;
}

// ✅ 或者将条件逻辑提取为子组件
function NameSection() {
  const [name, setName] = useState('');  // 独立组件，独立链表
  return <input value={name} onChange={e => setName(e.target.value)} />
}

ESLint 规则的必要性

eslint-plugin-react-hooks 中的 rules-of-hooks 规则会静态分析代码， 检测并报错任何在条件、循环或嵌套函数中调用 Hook 的行为。

  • 顶层调用 — Hook 必须在函数组件或自定义 Hook 的最顶层调用
  • 无条件 — 不要在 if / for / while 中调用
  • 无循环 — 不要在 for / map 回调中调用（除非数组长度永远不变）
  • 仅限组件 — 只在 React 函数组件或自定义 Hook 中调用
info
注意： useId 在 React 18+ 中也遵循此规则。 虽然它不依赖调用顺序，但为了规则一致性仍然要求顶层调用。 useSyncExternalStore 同理。

React 19 概览

React 19（2024 年 12 月正式发布）是一次重大版本升级，聚焦于异步状态管理、服务端组件、 编译器优化和开发者体验的全面改善。以下是最核心的更新：

bolt

1. Actions & 异步表单

React 19 将异步操作作为一等公民引入，新增 useActionState 和 useFormStatus：

'use client';
import { useActionState } from 'react';
import { useFormStatus } from 'react-dom';

function SubmitButton() {
  const { pending } = useFormStatus();  // 获取表单提交状态
  return (
    <button disabled={pending}>
      {pending ? '提交中...' : '提交'}
    </button>
  );
}

function Form() {
  const [state, formAction, isPending] = useActionState(
    async (prevState, formData) => {
      const result = await updateUser(formData);
      if (result.error) return { error: result.error };
      return { success: true };
    },
    { error: null }  // 初始状态
  );

  return (
    <form action={formAction}>
      <input name="name" />
      <SubmitButton />
      {state.error && <p>{state.error}</p>}
    </form>
  );
}
lightbulb
核心变化：<form action> 不再只是 URL，可以传入异步函数。 这意味着表单提交、乐观更新、错误处理都可以用声明式方式完成。
auto_awesome

2. use() — 在渲染中读取资源

use() 是 React 19 最具革命性的新 API，它可以在渲染期间读取 Promise 和 Context：

import { use } from 'react';

// ✅ 直接在组件渲染中 await — 不需要 useEffect + useState
function UserProfile({ userPromise }) {
  const user = use(userPromise);  // 挂起直到 Promise resolve

  return (
    <div>
      <h2>{user.name}</h2>
      <p>{user.email}</p>
    </div>
  );
}

// ✅ 条件读取 Context — 这是普通 useContext 做不到的
function ThemeText({ themePromise }) {
  if (condition) {
    const theme = use(ThemeContext);  // 可以在条件中调用！
    return <span style={{ color: theme.primary }}>Text</span>;
  }
  return <span>Default</span>;
}

React 18 模式

const [data, setData] = useState(null);
useEffect(() => {
  fetch(url).then(setData);
}, [url]);

React 19 模式

const data = use(promise);

3. ref 作为普通 prop

终于！ref 不再需要 forwardRef：

// ✅ React 19：ref 就是一个普通 prop
function Input({ placeholder, ref }) {
  return <input ref={ref} placeholder={placeholder} />;
}

// 父组件直接传
function Parent() {
  const inputRef = useRef(null);
  return <Input ref={inputRef} placeholder="输入..." />;
}

// ❌ React 18：需要 forwardRef 包裹（繁琐）
const Input = forwardRef((props, ref) => {
  return <input ref={ref} {...props} />;
});

4. useOptimistic — 乐观更新

import { useOptimistic } from 'react';

function TodoList({ todos, onAdd }) {
  const [optimisticTodos, addOptimistic] = useOptimistic(
    todos,
    (currentTodos, newTodo) => [...currentTodos, { ...newTodo, pending: true }]
  );

  async function handleAdd(formData) {
    const text = formData.get('text');
    addOptimistic({ text });     // 立刻显示在 UI 上
    await onAdd(text);             // 后台保存，失败自动回滚
  }

  return (
    <>
      <form action={handleAdd}>
        <input name="text" />
        <button>添加</button>
      </form>
      <ul>
        {optimisticTodos.map((t, i) => (
          <li key={i} style={{ opacity: t.pending ? 0.6 : 1 }}>
            {t.text}
          </li>
        ))}
      </ul>
    </>
  );
}

5. 更多重要更新

dns Server Components

RSC 正式稳定。组件可在服务端运行，零 JS bundle 发送到客户端，与客户端组件无缝组合。

cached 缓存改进

移除了 useMemo / useCallback / memo 的缓存保证，React Compiler 自动处理。

style 样式支持

原生支持 <style> 和 StyleSheet，SSR 时自动提取到 <head>。

script 脚本加载

新增 <Script> 组件和 preinit / preload API，智能管理第三方脚本。

title Metadata

原生支持 <title> / <meta> / <link> 在组件中声明，自动提升到 <head>。

error 错误改进

错误信息更精确，新增 onCaughtError / onUncaughtError 回调，控制台不再重复打印。

cleanup Cleanup 函数

ref 回调现在支持返回清理函数，替代之前的 useCallback hack。

compiler React Compiler

自动记忆化编译器（原 React Forget），无需手动 memo/useMemo/useCallback，编译器自动优化。

迁移建议

  • 逐步采用 — Server Components 和 Actions 可以按页面逐步迁移
  • 类型更新 — ref 作为 prop 后，组件类型签名更简洁
  • 移除手动 memo — 等 React Compiler 稳定后，逐步移除 useMemo / memo
